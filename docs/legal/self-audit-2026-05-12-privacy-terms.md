### §4 «Разрешения мобильного приложения ребёнка» — **TOP FINDING** 🟠

**4.2 Микрофон — критический конфликт с реальностью.**

Политика:

> Когда активируется: только в момент явного запроса родителя; **на устройстве ребёнка показывается уведомление о том, что аудиосессия запущена**.

Код (`apps/backend/prisma/schema.prisma:457`):

```prisma
model AudioSession {
  ...
  hiddenMode      Boolean             @default(true)
  ...
}
```

Backend service `apps/backend/src/audio/audio.service.ts:156`:

```typescript
const hiddenMode = (p.hiddenMode ?? true) && hiddenAllowed;
```

**То есть по умолчанию аудиосессия запускается в скрытом режиме без UI-уведомления ребёнку.** Управляется глобальным admin-флагом `AUDIO_HIDDEN_MODE_ALLOWED` (default true).

**Почему это серьёзно:**

- Несоответствие декларации в политике и фактического поведения — введение пользователя/субъекта в заблуждение. Для физлица-Оператора риск штрафа ст. 14.7 КоАП теоретический (не действует на сервисы вне B2C), но репутационный риск высокий.
- **Сложнее**: скрытая прослушка ребёнка без его уведомления — это другая legal-категория. Граничит со ст. 137 УК РФ (неприкосновенность частной жизни) и ст. 138 УК РФ (тайна переговоров). Прозрачный аудиомониторинг с уведомлением — допустимая практика парентал-контроля (см. практику «Где мои дети», Kaspersky Safe Kids), скрытая прослушка — серая зона.

**Варианты решения (требуют юриста + product-decision):**

| #   | Действие                                                                                             | Trade-off                                                                                                                         |
| --- | ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| A   | Удалить `hiddenMode` из кода (всегда показывать уведомление ребёнку)                                 | Несоответствие функциональности «Где мои дети». Возможна потеря части пользователей. RuStore-модерация — выше шансы.              |
| B   | Дефолт `hiddenMode=false`, оставить опцию по запросу родителя                                        | Промежуточный вариант. Юрист должен оценить, защищает ли это от ст. 138 УК даже когда родитель явно включил скрытый режим.        |
| C   | Оставить как есть, переписать политику честно («может работать в скрытом режиме по выбору родителя») | RuStore-модерация — критичный риск (попадание под stalkerware-policy). Иск от ребёнка/Роскомнадзора-проверки — реальный сценарий. |
| D   | Hybrid: hidden allowed только для детей до 14 (опекун-режим) + всегда уведомление для 14+            | Самый защищённый вариант, требует доработки разрешений в коде.                                                                    |

**Этот пункт обязательно к платной проверке.** Без юриста не править.

**4.5 AccessibilityService — оранжевый.**

Формулировка «GMD реагирует только на событие "открыто новое приложение" и сравнивает имя пакета со списком ограничений» — корректна. Но **юрист должен подтвердить**, что описание капабилити (это `BIND_ACCESSIBILITY_SERVICE` с broad-доступом к UI-событиям) + Device Admin + SAW + фоновая локация в совокупности не квалифицируются как «вредоносное ПО» по ст. 273 УК РФ.

Лессон #24 уже задокументирована: stalkerware-like profile = риск ремува из Play Store и блокировки на MIUI. Юридический риск отдельный — нужно профессиональное заключение, что заявленное целевое использование (родительский контроль) отграничивает от состава ст. 273.

**4.6 Device Admin — желательная правка.**

«GMD использует Device Admin исключительно для защиты от удаления» — корректно по факту. Но в коде есть `DeviceAdminReceiver.onPasswordChanged` callback (стандартный для класса). Юрист должен подтвердить, что наличие в коде неактивированных hooks не квалифицируется как «способность» (что важно для оценки риска).

**4.9 REQUEST_INSTALL_PACKAGES — желательная правка.**

«При установке через RuStore это разрешение не используется и не запрашивается» — корректно для установок из стора. Но при auto-update через ACTION_VIEW (наш текущий канал sideload-обновлений) это разрешение **используется**. Уточнить формулировку:

- «Используется только при доставке обновлений с серверов GMD (sideload-канал). При установке и обновлении через RuStore — не запрашивается.»

### §7 «Способы обработки» 🔴

**Текущая редакция:**

> Передача данных за пределы РФ **не осуществляется**.

**Проблема.** Это **некорректно**. Фактическая ситуация:

| Канал                          | Куда                                                 | Что передаётся                                                   |
| ------------------------------ | ---------------------------------------------------- | ---------------------------------------------------------------- |
| FCM (Firebase Cloud Messaging) | Google LLC, серверы за пределами РФ                  | Token устройства + push-payload (на момент доставки уведомлений) |
| RuStore Push (SDK)             | VK, серверы РФ                                       | Token устройства + push-payload                                  |
| Доставка email-OTP             | SMTP-провайдер (зависит от настройки `app_settings`) | Email-адрес + код                                                |

Для FCM передача push-token и payload в Google — это **трансграничная передача ПДн** (PUSH-токен квалифицируется как косвенный идентификатор устройства, связанного с субъектом).

**С 1 марта 2023** (Закон 233-ФЗ) перед началом трансграничной передачи оператор обязан подать в РКН уведомление по форме приказа РКН № 178 от 03.10.2022. Без этого — административная ответственность по ст. 13.11 КоАП (от 30 000 до 150 000 ₽ для гражданина, для ЮЛ от 1 до 6 млн).

**Что нужно сделать:**

1. **Срочно с юристом:** подать уведомление о трансграничной передаче в РКН (FCM → Google → США/глобальные ДЦ). Юрист должен:
   - Подготовить форму уведомления.
   - Оценить требования к «оценке достаточности защиты» (по приказу № 178) — в США нет режима, признанного РКН адекватным.
   - Решить, нужно ли получать **отдельное явное согласие** на трансграничную передачу (если применима ст. 12 152-ФЗ).
2. **Правка политики (после консультации с юристом):** заменить раздел 7 и добавить пункт «Трансграничная передача данных»:
   ```
   Для доставки push-уведомлений на устройства с Google Play Services
   используется Firebase Cloud Messaging (Google LLC, США). Передаётся
   только обезличенный токен устройства и текст уведомления. Передача
   осуществляется на основании [согласия / договора] в соответствии со
   ст. 12 152-ФЗ. Уведомление о трансграничной передаче подано в
   Роскомнадзор [дата].
   ```
3. **Альтернатива:** отключить FCM-канал полностью, оставить только RuStore Push (РФ-провайдер). Это срубает 50% пользовательской базы на устройствах с GMS — серьёзный product trade-off.

**Не править раздел 7 без юриста.** Это compliance-блокер.

| Категория                      | Где хранится      | Срок                                | Источник                              |
| ------------------------------ | ----------------- | ----------------------------------- | ------------------------------------- |
| Audit-log аудиосессий          | `audio_audit_log` | 1 год                               | `schema.prisma:481-485` (комментарий) |
| Зоновые события                | `zone_events`     | 30 дней                             | migration `20260420064916_*:31`       |
| Удалённые зоны (soft)          | `zones`           | 30 дней после deletedAt             | migration `20260420064916_*:40`       |
| Usage buckets (экранное время) | `usage_buckets`   | 30 дней                             | migration `20260426160000_*:79`       |
| Refresh-токены                 | `refresh_tokens`  | до revoke или истечения             | (бессрочно если не revoke'нуты)       |
| OTP-коды                       | `otp_codes`       | до использования / истечения 10 мин |                                       |

**Рекомендуемая правка (safe).** Добавить в §8:

```
- Технический журнал событий приложения (блокировки, аудит аудиосессий,
  зоновые события, SOS-сигналы) — 1 год после события; необходим для
  расследования инцидентов безопасности и ответов на жалобы.
- Refresh-токены сессий — до момента выхода пользователя или истечения
  срока действия (90 дней с момента выпуска).
- Одноразовые коды (OTP) — 10 минут или до использования.
```

**Сделаю safe-fix** — это повышение прозрачности, не меняет суть.

**Текущая редакция:**

### §4 «Правила использования» 🟡

**Текущая редакция:**

**Уточнить с юристом.** Можно сделать сейчас safe-fix: добавить в §4 явное упоминание ответственности по ст. 137-138 УК РФ.

## Доп. вопросы вне текстов

### Регистрация в реестре операторов ПДн (РКН) 🔴

После Закона 266-ФЗ от 14.07.2022 (вступил с 1 сентября 2022) **обязанность подачи уведомления расширена практически до всех операторов**. Исключения в ч. 2 ст. 22 152-ФЗ урезаны и для нашего кейса (обработка детских данных, геолокация, аудио) **не применимы**.

**Действия:**

1. Юрист подтверждает обязательность уведомления.
2. Оператор подаёт уведомление по форме РКН (онлайн через `pd.rkn.gov.ru`) — указывая категории субъектов, состав данных, цели, сроки, меры защиты.
3. Получение записи в реестре.
4. Указание реестрового номера в §1 политики.

**Срок:** обычно 1-2 недели после подачи. До этого работа продолжается «на свой страх и риск» — при проверке РКН штраф по ст. 19.7 КоАП (300-500 ₽ для физлица — почти символический, но при систематическом — может быть выше).

### Runbook инцидентов ИБ 🟡

Ст. 21 ч. 3.1 152-ФЗ (с 1 сентября 2022): при утечке ПДн оператор обязан в течение 24 часов уведомить РКН и Государственную систему обнаружения, предупреждения и ликвидации последствий компьютерных атак (ГосСОПКА), и в течение 72 часов передать результаты внутреннего расследования.

**Действия:**

1. Создать `docs/runbooks/data-breach-notification.md`:
   - Триггеры (что считаем утечкой).
   - Шаблон уведомления в РКН.
   - Контакт ГосСОПКА (для физлица-Оператора без подключения к ГосСОПКА — отдельно уточнить, нужна ли регистрация).
   - Шаги расследования.
2. Юрист должен сказать, обязательно ли регистрировать в ГосСОПКА (для маленького физлица-Оператора — возможно, нет, но в законе формулировка общая).
