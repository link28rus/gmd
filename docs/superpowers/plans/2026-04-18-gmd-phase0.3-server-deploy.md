# GMD Phase 0.3 — Server Deploy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Поднять production-стек GMD на сервере `192.168.1.23` (Ubuntu 24.04, VMware VM) с TLS через Caddy+Let's Encrypt на домене `gmd.link28rus.ru`, harden SSH, включить UFW + fail2ban, настроить pg_cron retention локаций на 30 дней, ежедневные бэкапы PG с verify-restore, GlitchTip для ошибок и Uptime Kuma для внешнего мониторинга.

**Architecture:**

- **Хост:** Ubuntu 24.04 LTS, 8 GiB RAM, 80 GB диск (после расширения `sda2`), hostname `gmd-prod`. Доступ только по SSH-ключу, PasswordAuth off, root-logins через pubkey.
- **Стек:** Docker Compose v2 разворачивает: `postgres` (postgis/postgis:16-3.4 + pg_cron через custom image), `redis`, `minio`, `backend` (NestJS), `web` (Next.js), `caddy` (reverse proxy + TLS), `glitchtip` (+ его postgres+redis), `uptime-kuma`. Все сервисы — одна private сеть `gmd_net`; наружу торчат только `caddy:80/443`. Backend и web только через Caddy.
- **Данные:** bind-mount в `/opt/gmd/data/{postgres,redis,minio,caddy,glitchtip-pg,uptime-kuma}`. Бэкапы PG в `/opt/gmd/backups/postgres/` через systemd-timer `pg-backup.timer` ежедневно 03:15 UTC; retention 14 ежедневных + 12 месячных; еженедельный verify-restore в отдельный throwaway-контейнер.
- **Приватность:** retention локаций 30 дней через `pg_cron` job — работает внутри контейнера Postgres.
- **Деплой:** с локальной Windows-машины через `infra/deploy/deploy.sh` (выполняется в msys2 bash): `rsync` `infra/docker/` и `infra/caddy/` на сервер в `/opt/gmd/`, потом `ssh` → `docker compose -f /opt/gmd/docker-compose.prod.yml up -d`. Backend/web пока собираются из исходников прямо на сервере (multi-stage Dockerfile); в Phase 0.4 перейдём на реестр образов.

**Tech Stack:**

- Сервер: Ubuntu 24.04 LTS, Docker CE + compose-plugin (из официального `download.docker.com`), UFW, fail2ban, OpenSSH 9.x.
- Контейнеры: `postgis/postgis:16-3.4` (с установкой pg_cron поверх — custom Dockerfile), `redis:7-alpine`, `bitnami/minio:2024`, `caddy:2-alpine`, `glitchtip/glitchtip:v4.1`, `louislam/uptime-kuma:1`, `postgres:15-alpine` (для GlitchTip — отдельная БД), `node:22-alpine` (builder для backend/web).
- Prod compose: `infra/docker/docker-compose.prod.yml`, `.env.prod` (вне git), override для secrets.
- TLS: Caddy v2 автоматический ACME через Let's Encrypt, e-mail в `CADDY_ACME_EMAIL=admin@link28rus.ru`.
- Backup: `pg_dump -Fc` + `zstd -19`, хранение локально + опциональный `rsync` на NAS (заготовка, в 0.3 не включаем).

## Task 2: Обновить ОС, установить hostname, timezone, swap

**Files:**

- SSH-команды.
- Create: `infra/server-setup/00-bootstrap.sh` (reproducible).

- [ ] **Step 1: Создать скрипт `00-bootstrap.sh`**

Создать файл `infra/server-setup/00-bootstrap.sh`:

```bash
#!/usr/bin/env bash
# GMD prod bootstrap — запускать на свежей Ubuntu 24.04 (root).
# Idempotent: можно прогонять повторно.
set -euo pipefail

echo "==> apt update + full-upgrade"
export DEBIAN_FRONTEND=noninteractive
apt-get update -q
apt-get full-upgrade -yq
apt-get install -yq --no-install-recommends \
  ca-certificates curl gnupg lsb-release \
  htop iotop ncdu zstd jq rsync \
  cloud-guest-utils unattended-upgrades

echo "==> hostname -> gmd-prod"
hostnamectl set-hostname gmd-prod
grep -q '^127.0.1.1' /etc/hosts && sed -i 's/^127.0.1.1.*/127.0.1.1\tgmd-prod/' /etc/hosts || echo '127.0.1.1\tgmd-prod' >> /etc/hosts

echo "==> timezone -> Europe/Moscow"
timedatectl set-timezone Europe/Moscow

echo "==> swap 4G (если нет)"
if ! swapon --show | grep -q '/swapfile'; then
  fallocate -l 4G /swapfile
  chmod 600 /swapfile
  mkswap /swapfile
  swapon /swapfile
  grep -q '/swapfile' /etc/fstab || echo '/swapfile none swap sw 0 0' >> /etc/fstab
fi

echo "==> unattended-upgrades enabled"
dpkg-reconfigure -fnoninteractive unattended-upgrades

echo "==> bootstrap done"
```

## Task 6: SSH hardening — disable PasswordAuthentication, PermitRootLogin prohibit-password

**Files:**

- Create: `infra/server-setup/10-harden-ssh.sh`

- [ ] **Step 1: Создать скрипт `10-harden-ssh.sh`**

```bash
#!/usr/bin/env bash
# GMD — hardening sshd.
# ВНИМАНИЕ: перед запуском убедись, что ключ в /root/.ssh/authorized_keys работает (ssh -o PasswordAuthentication=no root@host 'echo ok').
set -euo pipefail

CONF=/etc/ssh/sshd_config.d/99-gmd-hardening.conf
cat > "$CONF" <<'EOF'
# GMD hardening (overrides /etc/ssh/sshd_config and 50-cloud-init.conf)
PasswordAuthentication no
KbdInteractiveAuthentication no
ChallengeResponseAuthentication no
PermitRootLogin prohibit-password
PubkeyAuthentication yes
PermitEmptyPasswords no
MaxAuthTries 3
LoginGraceTime 20s
ClientAliveInterval 300
ClientAliveCountMax 2
X11Forwarding no
AllowAgentForwarding no
AllowTcpForwarding no
Protocol 2
EOF

# Также вырежем противоречивую строку в 50-cloud-init.conf
if grep -q '^PasswordAuthentication yes' /etc/ssh/sshd_config.d/50-cloud-init.conf 2>/dev/null; then
  sed -i 's/^PasswordAuthentication yes/PasswordAuthentication no/' /etc/ssh/sshd_config.d/50-cloud-init.conf
fi

# Валидация
sshd -t
echo "==> sshd config OK. Restart sshd…"
systemctl restart ssh
systemctl --no-pager status ssh | head -5
```

```bash

ssh gmd-prod 'chmod +x /root/10-harden-ssh.sh && /root/10-harden-ssh.sh'
```

Expected: `sshd config OK`, `Active: active (running)`.

- [ ] **Step 3: Верификация — вход по паролю ДОЛЖЕН сломаться**

```sql
-- Файл называется 20-retention.sql; init.sql переименуем в 10-init.sql.

-- Таблица locations ещё не создана (появится в backend Prisma-миграциях Phase 1).

DO $$
```

```bash
#!/usr/bin/env bash
# Снимает pg_dump -Fc из контейнера postgres, сжимает zstd, кладёт в /opt/gmd/backups/postgres/.
set -euo pipefail
umask 077

BACKUP_DIR=/opt/gmd/backups/postgres
DATE=$(date -u +%Y-%m-%d_%H%M)
FILE="${BACKUP_DIR}/gmd-${DATE}.dump"
LOCK=/var/lock/gmd-pg-backup.lock

mkdir -p "${BACKUP_DIR}"

exec 9>"$LOCK"
flock -n 9 || { echo "Another backup in progress; exiting."; exit 0; }

# Загружаем пароль из .env.prod
set -a; . /opt/gmd/.env.prod; set +a

docker exec -i gmd-postgres pg_dump -U "${POSTGRES_USER}" -d "${POSTGRES_DB}" -Fc -Z0 > "${FILE}"

zstd -19 --rm -q "${FILE}"
# Итог: gmd-YYYY-MM-DD_HHMM.dump.zst

SHA=$(sha256sum "${FILE}.zst" | awk '{print $1}')
echo "${SHA}  $(basename ${FILE}.zst)" >> "${BACKUP_DIR}/SHA256SUMS"

# Первый бэкап месяца — помечаем как monthly
DAY_OF_MONTH=$(date -u +%d)
if [ "${DAY_OF_MONTH}" = "01" ]; then
  ln "${FILE}.zst" "${BACKUP_DIR}/monthly-$(date -u +%Y-%m).dump.zst"
fi

echo "Backup OK: ${FILE}.zst ($(du -h ${FILE}.zst | awk '{print $1}'))"

/opt/gmd/bin/pg-retention.sh
```

```bash
#!/usr/bin/env bash
# Еженедельный тест: поднять throwaway postgres, залить последний dump, проверить счётчики.
set -euo pipefail
umask 077

BACKUP_DIR=/opt/gmd/backups/postgres
LATEST=$(ls -1t "${BACKUP_DIR}"/gmd-*.dump.zst 2>/dev/null | head -1)

if [ -z "${LATEST}" ]; then
  echo "No backups found, skipping verify."
  exit 0
fi

set -a; . /opt/gmd/.env.prod; set +a

TMP_CONTAINER=gmd-restore-verify-$$
TMP_VOLUME=gmd-restore-verify-vol-$$

docker run -d --name "${TMP_CONTAINER}" \
  -e POSTGRES_PASSWORD=verify \
  -v "${TMP_VOLUME}:/var/lib/postgresql/data" \
  gmd-postgres:16-postgis-pgcron \
  postgres -c shared_preload_libraries=pg_cron -c cron.database_name=postgres

# Ждём готовности
for i in {1..30}; do
  if docker exec "${TMP_CONTAINER}" pg_isready -U postgres >/dev/null 2>&1; then break; fi
  sleep 1
done

# Создаём целевую БД
docker exec "${TMP_CONTAINER}" psql -U postgres -c "CREATE DATABASE ${POSTGRES_DB} OWNER postgres;"

# Restore
zstd -dc "${LATEST}" | docker exec -i "${TMP_CONTAINER}" pg_restore -U postgres -d "${POSTGRES_DB}" --no-owner --no-privileges

# Smoke-check
TABLES=$(docker exec "${TMP_CONTAINER}" psql -U postgres -d "${POSTGRES_DB}" -tAc \
  "SELECT count(*) FROM information_schema.tables WHERE table_schema='public'")
echo "Restored backup has ${TABLES} tables in public schema."

# Cleanup
docker rm -fv "${TMP_CONTAINER}"
docker volume rm "${TMP_VOLUME}"

if [ "${TABLES}" -gt 0 ]; then
  echo "Restore verify: OK ($(basename ${LATEST}))"
else
  echo "Restore verify: WARN — 0 tables (может быть нормально на пустом кластере Phase 0.3)"
fi
```

```typescript
import { ArgumentsHost, Catch, ExceptionFilter, HttpException } from '@nestjs/common';
import * as Sentry from '@sentry/node';

@Catch()
export class SentryExceptionFilter implements ExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const res = ctx.getResponse();
    const status = exception instanceof HttpException ? exception.getStatus() : 500;
    if (status >= 500) Sentry.captureException(exception);
    const message =
      exception instanceof HttpException ? exception.getResponse() : 'Internal server error';
    res
      .status(status)
      .json(typeof message === 'string' ? { statusCode: status, message } : message);
  }
}
```
