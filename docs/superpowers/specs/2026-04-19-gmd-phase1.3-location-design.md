# GMD Phase 1.3 — Location Ingestion (design)

**Дата:** 2026-04-19
**Фаза:** 1.3
**Предшественник:** v0.9.0 (Phase 1.2.5 — privacy/consent)
**Релизная цель:** v0.10.0 (backend-only)

## 1. Область и не-область

### Что входит

- Приём GPS-точек батчами от устройства ребёнка: `POST /child/locations`.
- Чтение родителем: `GET /children/:id/location/latest`, `GET /children/:id/locations`.
- Retention 30 дней через `pg_cron`.
- Валидация clock-skew, rate-limit, идемпотентность по `(device, recordedAt)`.
- Новый переиспользуемый `FamilyAccessGuard`.

### Что НЕ входит

- Геозоны + push при входе/выходе — Phase 2.
- SOS — Phase 2.
- Карта и история в web-кабинете родителя — Phase 1.3-web.
- Mobile-child Flutter-клиент — Phase 3.
- Downsampling на чтении — появится в Phase 1.3-web, когда будет понятен профиль запросов.
- WebSocket/SSE (по решению MVP — short-polling + push, без WS).

## 2. Модель данных

### Prisma

```prisma
model Location {
  id               String   @id @default(cuid())
  childId          String
  childDeviceId    String
  lat              Float
  lon              Float
  accuracy         Float?        // метры
  altitude         Float?        // метры
  speed            Float?        // м/с
  bearing          Float?        // 0..360
  batteryLevel    Int?          // 0..100
  isCharging       Boolean?
  provider         String?       // gps | fused | network
  recordedAt       DateTime      // время с устройства
  serverReceivedAt DateTime @default(now())

  child       Child       @relation(fields: [childId], references: [id], onDelete: Cascade)
  childDevice ChildDevice @relation(fields: [childDeviceId], references: [id], onDelete: Cascade)

  @@unique([childDeviceId, recordedAt])
  @@index([childId, recordedAt(sort: Desc)])
  @@map("locations")
}
```

Обратные поля: `Child.locations Location[]`, `ChildDevice.locations Location[]`.

### Raw SQL (в той же миграции, после Prisma-части)

```sql
ALTER TABLE locations
  ADD COLUMN geom geography(Point, 4326)
  GENERATED ALWAYS AS (ST_SetSRID(ST_MakePoint(lon, lat), 4326)::geography) STORED;

CREATE INDEX locations_geom_gist ON locations USING GIST (geom);
```

`geom` — generated column: источник правды — `lat/lon`, геометрия выводится автоматически, рассинхрон невозможен. Используется в Phase 2 для `ST_DWithin` по геозонам.

### Валидация входных точек (Zod в DTO)

- `lat` ∈ [−90, 90]; `lon` ∈ [−180, 180]; до 6 знаков после запятой (≈ 11 см).
- `recordedAt` ∈ [`now − 24h`, `now + 2min`]. Вне окна → точка отбрасывается с причиной `out_of_window`.
- `accuracy >= 0` (опциональное); `speed >= 0`; `bearing` ∈ [0, 360).
- `batteryLevel` ∈ [0, 100]; `provider` ∈ {`gps`, `fused`, `network`}.
- Размер батча: `1..100` точек.

## 3. API-контракт

### Write (child) — `POST /child/locations`

Guards: `ChildAuthGuard` (уже существует, `X-Child-Token`).

```json
{
  "points": [
    {
      "lat": 55.751244,
      "lon": 37.618423,
      "recordedAt": "2026-04-19T10:23:45.000Z",
      "accuracy": 8.5,
      "altitude": 156.0,
      "speed": 1.2,
      "bearing": 92.0,
      "batteryLevel": 73,
      "isCharging": false,
      "provider": "fused"
    }
  ]
}
```

Успех `200`:

```json
{
  "accepted": 12,
  "rejected": 3,
  "rejectedReasons": { "out_of_window": 2, "duplicate": 1 }
}
```

Ошибки:

| Код | code                | Когда                                             |
| --- | ------------------- | ------------------------------------------------- |
| 400 | `invalid_payload`   | Zod-валидация не прошла (формат, диапазоны полей) |
| 401 | `unauthorized`      | Нет или битый `X-Child-Token`                     |
| 403 | `device_revoked`    | `ChildDevice.revokedAt != null`                   |
| 404 | `child_not_found`   | `Child.deletedAt != null` (soft-deleted)          |
| 413 | `batch_too_large`   | `points.length > 100` (отдельная проверка до Zod) |
| 423 | `consent_required`  | Owner семьи не принял `PRIVACY_POLICY_VERSION`    |
| 429 | `too_many_requests` | Rate-limit > 6 req/min per device; `Retry-After`  |

Чтобы `413` был явно отделён от `400`, `points.length > 100` проверяется в контроллере **до** Zod-разбора элементов. Zod валидирует только `points.min(1)` и каждую точку по отдельности.

Rate-limit: `@nestjs/throttler`, tracker по `req.childDevice.deviceId`, 6 req / 60s. Backend single-instance, memory-storage ок для MVP; миграция на Redis — Phase 2.

### Read (parent) — JWT + `FamilyAccessGuard`

#### `GET /children/:id/location/latest`

`200`:

```json
{
  "lat": 55.751244,
  "lon": 37.618423,
  "recordedAt": "2026-04-19T10:23:45.000Z",
  "serverReceivedAt": "2026-04-19T10:23:46.120Z",
  "accuracy": 8.5,
  "altitude": 156.0,
  "speed": 1.2,
  "bearing": 92.0,
  "batteryLevel": 73,
  "isCharging": false,
  "provider": "fused",
  "ageSec": 42
}
```

`204 No Content` — точек ещё нет.

#### `GET /children/:id/locations`

Query:

- `from` ISO (default: начало суток в таймзоне сервера = UTC)
- `to` ISO (default: `now`)
- `limit` 1..2000 (default 500)
- `cursor` ISO (опционально)
- `order` `asc` | `desc` (default `desc`)

`200`:

```json
{
  "items": [ { /* Location */ }, ... ],
  "nextCursor": "2026-04-19T09:50:00.000Z"
}
```

`nextCursor` = `recordedAt` последнего элемента в `items`. `null` если страница последняя.

Ошибки чтения:

| Код | code              | Когда                                                            |
| --- | ----------------- | ---------------------------------------------------------------- |
| 401 | `unauthorized`    | Нет JWT                                                          |
| 404 | `child_not_found` | Ребёнок не существует, soft-deleted, ИЛИ не в семье пользователя |

Любой случай «нет доступа» отдаёт один и тот же 404, чтобы не раскрывать существование чужих детей. Это сознательный trade-off: ошибка менее информативна, зато нет enumeration-атаки.

## 4. Архитектура (NestJS)

```
apps/backend/src/locations/
├── locations.module.ts
├── locations.controller.ts       # POST /child/locations (ChildAuthGuard)
├── locations-read.controller.ts  # GET /children/:id/... (JwtAuthGuard + FamilyAccessGuard)
├── locations.service.ts
├── dto/
│   ├── ingest-locations.dto.ts
│   └── list-locations.dto.ts
├── guards/
│   └── family-access.guard.ts    # проверяет, что :id в семье req.user
├── locations.service.spec.ts
├── locations.controller.spec.ts
└── locations.e2e.spec.ts         # Testcontainers + PostGIS
```

Подключение: `LocationsModule` импортируется в `AppModule`. Зависит от `PrismaModule`, `ChildDeviceModule` (для `ChildAuthGuard`), `AuthModule` (для `JwtAuthGuard`).

### Сервис `locations.service.ts`

Публичные методы:

- `ingestBatch(ctx: ChildDeviceContext, points: IngestPoint[]): Promise<IngestResult>`
  1. Проверка `Child.deletedAt == null`, иначе 404.
  2. Проверка `ChildDevice.revokedAt == null`, иначе 403.
  3. Проверка consent owner'а семьи: найти owner'а → user.acceptedPrivacyPolicyVersion == config.currentPolicyVersion. Кэш in-memory на 60с per `childId`, ключ `consent:${childId}`. Stale до 60с приемлем.
  4. Для каждой точки: проверить окно → если вне → rejectedReasons.out_of_window++. Оставшиеся сериализуются и отправляются одним `INSERT ... ON CONFLICT (child_device_id, recorded_at) DO NOTHING RETURNING id`. Разница `points.length - returning.length` → rejectedReasons.duplicate.
  5. Вернуть `{ accepted, rejected, rejectedReasons }`.

  `touchLastSeen(deviceId)` уже делает `ChildAuthGuard` → дублировать не надо.

- `getLatest(childId: string): Promise<LocationDto | null>`
  `prisma.location.findFirst({ where: { childId }, orderBy: { recordedAt: 'desc' } })`.
  Вычислить `ageSec = (now − recordedAt) / 1000`.

- `list(childId: string, query: ListQuery): Promise<{ items, nextCursor }>`
  Применить `from`, `to`, `cursor` (если `order=desc` → `recordedAt < cursor`, иначе `>`). `orderBy.recordedAt = order`. `take = limit`.

### Новый `FamilyAccessGuard`

- Вход: JWT-user из `req.user` + `:id` ребёнка из params.
- Запрос: `prisma.child.findFirst({ where: { id: :id, family: { memberships: { some: { userId } } } } })`.
- `null` → 404 `child_not_found`.
- `child.deletedAt` → 404 `child_not_found`.
- Иначе — `req.targetChild = child` и `return true`.
- Спец-случай: если child в другой семье — тоже 404 (а не 403), чтобы не раскрывать существование. В документации указать это поведение.

## 5. Retention (pg_cron)

Миграция (raw SQL, идемпотентно):

```sql
DO $$
BEGIN
  IF EXISTS (SELECT 1 FROM cron.job WHERE jobname = 'locations-retention-daily') THEN
    PERFORM cron.unschedule('locations-retention-daily');
  END IF;
END $$;

SELECT cron.schedule(
  'locations-retention-daily',
  '0 3 * * *',
  $$DELETE FROM locations WHERE recorded_at < now() - interval '30 days'$$
);
```

Расписание: каждый день 03:00 UTC (06:00 MSK) — минимальная нагрузка.

Мониторинг: `SELECT * FROM cron.job_run_details WHERE jobname='locations-retention-daily' ORDER BY start_time DESC LIMIT 10;`

Будущее: если таблица уйдёт за ~20M строк и `DELETE` станет тяжёлым — переехать на partitioning по дню + `DROP PARTITION`. На MVP не делаем, ведём tracking-метрику «размер таблицы».

## 6. Приватность и 152-ФЗ

- **Consent-gate на приёме**: если владелец семьи не принял текущую `PRIVACY_POLICY_VERSION` → 423 `consent_required`. Клиент-ребёнок буферизует локально, шлёт при следующей возможности. Стимулирует родителя обновить согласие.
- **Каскад удалений**: soft-delete `Child` → новые точки отвергаются (404). Уже записанные точки живут до естественного истечения retention (30 дней) или до hard-delete ребёнка. Hard-delete через `onDelete: Cascade` вычищает всё.
- **Координаты в логах** — НЕТ. В INFO-лог только `{ childId, deviceId, accepted, rejected }`. Ошибки (GlitchTip) — без payload.

## 7. Безопасность

- Rate-limit per device (6 req/min), не per IP.
- Ответ на батч не раскрывает, какая точка отбросилась — только агрегированные счётчики. Нельзя зондировать clock-skew или состояние дедупа построчно.
- `FamilyAccessGuard` не различает 403 и 404 — всегда 404 `child_not_found` при любом отсутствии доступа, чтобы не раскрывать существование чужих детей.
- `X-Child-Token`: хранится как `tokenHash` (уже реализовано).

## 8. Тестирование (TDD)

### Unit — `locations.service.spec.ts` (мок Prisma)

- `ingestBatch`: accepted / out_of_window_past / out_of_window_future / duplicate — по одной точке на сценарий.
- `ingestBatch`: агрегация счётчиков по смешанному батчу.
- `ingestBatch`: consent не принят → `ConsentRequiredException` (HTTP 423).
- `ingestBatch`: `Child.deletedAt != null` → `NotFoundException`.
- `ingestBatch`: `ChildDevice.revokedAt != null` → `ForbiddenException`.
- `ingestBatch`: consent cache hit/miss.
- `getLatest`: точки есть / нет.
- `list`: пагинация курсором (asc и desc), границы `from`/`to`, `limit`-кап.

### Unit — `family-access.guard.spec.ts`

- Owner семьи → allow.
- Parent-member → allow.
- Другой юзер → 404 `child_not_found`.
- Child в soft-deleted состоянии → 404.

### Unit — `locations.controller.spec.ts`

- Zod-валидация: невалидные поля → 400.
- Batch > 100 → 413.
- Проход через `ChildAuthGuard` mock, корректная передача `req.childDevice` в сервис.

### E2E — `locations.e2e.spec.ts` (Testcontainers)

- Happy path: регистрация родителя (helper есть) → создать ребёнка → claim invite → отправить батч через `X-Child-Token` → `GET /latest` и `GET /locations` от родителя совпадают.
- 423 при неактуальном consent родителя.
- 429 на 7-м запросе подряд (rate-limit).
- 413 при batch > 100.
- Идемпотентность: одна и та же точка дважды → первая accepted, вторая duplicate.
- PostGIS-столбец `geom` заполнен (raw SQL проверка `ST_X(geom::geometry), ST_Y(geom::geometry)`).
- Retention: INSERT старой записи с `recorded_at = now() - 31 day` → ручной вызов `DELETE ... WHERE recorded_at < now() - interval '30 days'` → исчезла.
- `FamilyAccessGuard`: другой пользователь → 404.

### Не тестируем

- pg_cron как скедулер (доверяем Postgres). Проверяем только SQL-запрос, который он выполняет.
- Prometheus-метрики (нет в MVP).

## 12. Риски и митигации

| Риск                                        | Митигация                                                                                                                                  |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Memory-throttler не кластеризуется          | MVP single-instance; на Phase 2 переводим на Redis-store                                                                                   |
| Consent-cache 60с → stale разрешение        | Допустимо: после отзыва родителем policy — max 60с ингеста продолжится. Consent UI уже ставит current ver сразу → это окно при bump версии |
| `DELETE` миллионов строк раз в день → bloat | MVP — объём низкий. Tracking size; partitioning при росте                                                                                  |
| Clock-skew клиента > 2 мин                  | Точка отбрасывается с `out_of_window`. Клиент синхронизирует NTP                                                                           |
| Злоумышленник с валидным токеном льёт мусор | Rate-limit 6/min; quota per day — отложено до первого инцидента                                                                            |
