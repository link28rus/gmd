# Геозоны v2 — спецификация

Дата: 2026-09-29. Решения пользователя приняты 29.09.2026 после разведки кода трёх слоёв
(backend, web, mobile-parent) и трёх исследований: как устроены геозоны у лидеров рынка,
технические практики детекции, локальные базы GeoIP. Каждый этап — отдельная версия.

| Этап | Версия | Слои                   | Суть                                                  |
| ---- | ------ | ---------------------- | ----------------------------------------------------- |
| 1    | 0.64.0 | backend + web          | Надёжная детекция, кабинет зон, центр карты, GeoIP    |
| 2    | 0.65.0 | backend + web          | Личные настройки уведомлений, расписание, «не пришёл» |
| 3    | 0.66.0 | mobile-parent (APK)    | Нативный экран геозон, переход из push, «Где я»       |
| 4    | 0.67.0 | backend + web + parent | Подсказки мест по частым стоянкам                     |

Не делаем: полигоны и «тихие часы» — у лидеров рынка их нет, зоны у всех круглые.

Предусловие для push: на проде задан ключ сервисного аккаунта Firebase (`FIREBASE_SA_KEY`),
backend при старте пишет `FCM initialized` (проверено 29.09.2026).

## Этап 1 «Надёжность и кабинет» (0.64.0)

### 1.1 Детекция с учётом погрешности

Детекция идёт на сервере при приёме точек (`LocationsService.ingest` →
`ZoneDetectionService.processPoint`). Телефон ребёнка о зонах ничего не знает.

Для каждой пары зона × ребёнок: `d` — расстояние от точки до центра (PostGIS
`ST_Distance` по geography), `acc` — погрешность точки в метрах (нет — 0), `R` — радиус,
`B = max(30, 0.15·R)` — буфер.

| Условие           | Вердикт                                                   |
| ----------------- | --------------------------------------------------------- |
| `d + acc/2 ≤ R`   | внутри                                                    |
| `d − acc > R + B` | снаружи                                                   |
| иначе             | неясно — состояние не меняется, `pending` не сбрасывается |

- Вердикт совпал с состоянием → сбросить `pending`.
- Вердикт отличается → если `pending` нет, поставить `pendingSince = recordedAt`; если есть и
  прошло ≥ 60 с по времени фикса (`DEBOUNCE_MS`) — событие `entry`/`exit`, новое состояние.
- Кандидаты — все зоны, применимые к ребёнку (`allChildren` или назначение), без
  `ST_DWithin`: зон в семье не больше 20, а отсечение по `R + B` теряло точки с большой
  погрешностью. Формула буфера живёт в одном месте — `buffer()` в `zone-detection.service.ts`.
- Нет строки `ZoneState` (ребёнок добавлен в семью после создания зоны «для всех») —
  первая однозначная точка молча задаёт состояние, без события.
- Точки `outlier` и `mock`, а также «старый хвост» офлайн-очереди в зоны не идут
  (как в 0.59–0.63). Грубые `coarse` идут — их гасит формула с `acc`.
- Гонка двух одновременных пачек одного ребёнка: `pg_advisory_xact_lock` по ребёнку
  внутри транзакции приёма, перед расчётом зон.

**Пример.** Зона `R = 150`, `B = 30`. Точка с `acc = 60` внутри, если `d ≤ 120`,
снаружи — если `d > 240`. Ночная точка из квартиры с `acc = 90` на `d = 200` — «неясно»,
ложного «ушёл из дома» не будет.

### 1.2 Начальное состояние

При создании зоны, добавлении ребёнка в зону и правке центра или радиуса состояние
считается по последней хорошей точке ребёнка (`trackFlag` не `outlier` и не `mock`) —
**без события**, `pending` сбрасывается, `lastConfirmedChange = null`.
Однозначный вердикт берётся по формуле 1.1, «неясно» — по `d ≤ R`. Точек нет — «снаружи».
Раньше состояние всегда создавалось «снаружи», и ребёнок, стоящий внутри новой зоны,
через минуту давал ложный «вход» с push.

### 1.3 Push после commit

`processPoint` возвращает созданные события, `LocationsService` рассылает push
**после** успешного commit транзакции приёма. Раньше push уходил изнутри транзакции:
откат давал push без события, повтор запроса — дубль.

### 1.4 Модель и API

Миграция `20261001100000_zones_v2_all_children`:

- `zones."allChildren" BOOLEAN NOT NULL DEFAULT false` — зона для всех детей семьи,
  включая будущих;
- `zone_events."durationSec" INTEGER NULL` — у события выхода: сколько ребёнок пробыл
  в зоне (от подтверждённого входа). `null`, если вход не наблюдался (начальное
  состояние, зона создана при ребёнке внутри).
- Колонку `zones.center_geo` (generated geography + GIST) Prisma не видит: при
  `migrate diff` строку `DROP COLUMN "center_geo"` вычищать руками.

CHECK в БД на радиус (50..5000) не трогаем. Zod: радиус 100..5000 (в UI по умолчанию 150).

`familyId` во всех ручках зон — из JWT (`req.user.familyId`), как в `children.controller`.

#### `POST /zones`, `PATCH /zones/:id`

```jsonc
{
  "name": "Школа", // 1..60
  "color": "#22c55e", // палитра из 6 цветов
  "icon": "school",
  "centerLat": 48.48,
  "centerLon": 135.08,
  "radius": 150, // 100..5000
  "allChildren": true, // POST: по умолчанию false; PATCH: необязательно
  "childIds": ["c..."], // уникализируются, не больше 50; при allChildren=true игнорируются
}
```

При `allChildren = true` явные назначения удаляются, состояния создаются для всех
текущих детей семьи. При снятии флага остаются только дети из `childIds`, лишние
состояния удаляются.

Ошибки: `400 validation_failed`, `404 child_not_found`, `404 zone_not_found`,
`409 zone_limit_reached` (20 зон).

#### `ZoneDto`

```jsonc
{
  "id": "…",
  "familyId": "…",
  "name": "…",
  "color": "#22c55e",
  "icon": "home",
  "centerLat": 0,
  "centerLon": 0,
  "radius": 150,
  "allChildren": true,
  "childIds": ["…"], // явные назначения (пусто при allChildren)
  "states": [{ "childId": "…", "isInside": true }],
  "createdBy": "…",
  "createdAt": "…",
  "updatedAt": "…",
}
```

#### `GET /zones/events?childId=&zoneId=&from=&to=&cursor=&limit=`

Порядок `(recordedAt desc, id desc)`. `cursor` — непрозрачная строка из `nextCursor`
(base64url от пары `recordedAt` + `id`): события с одинаковым временем на границе
страницы больше не теряются. `limit` 1..100, по умолчанию 50.

```jsonc
{
  "items": [
    {
      "id": "…",
      "zoneId": "…",
      "zoneName": "…",
      "zoneColor": "#…",
      "zoneIcon": "home",
      "childId": "…",
      "childName": "…",
      "type": "exit", // entry | exit
      "lat": 0,
      "lon": 0,
      "accuracy": 12,
      "recordedAt": "…", // время фикса — его и показывать
      "createdAt": "…",
      "durationSec": 5400, // только у exit, иначе null
    },
  ],
  "nextCursor": "…", // или null
}
```

#### `GET /family/locations/latest`

Последняя хорошая точка (без `outlier` и `mock`) каждого ребёнка семьи одним запросом.
Дети без точек в ответ не попадают.

```jsonc
{
  "items": [
    { "childId": "…", "lat": 0, "lon": 0, "accuracy": 15, "recordedAt": "…", "ageSec": 120 },
  ],
}
```

#### `GET /geo/ip-center`

JWT + throttle 30/мин. Город по IP клиента из локальной базы DB-IP City Lite.
Под `/api/geo/*` Caddy шлёт запрос прямо в backend, `req.ip` реальный (`trust proxy`).
Приватный или служебный адрес, нет в базе, база не загружена — `204`.

```jsonc
{
  "lat": 48.48,
  "lon": 135.07,
  "city": "Khabarovsk",
  "countryCode": "RU",
  "attribution": "IP Geolocation by DB-IP",
}
```

IP никуда не уходит: база лежит на сервере (152-ФЗ).

### 1.5 GeoIP

- База: DB-IP City Lite (CC BY 4.0), файлы `dbip-city-ipv4.mmdb` и `dbip-city-ipv6.mmdb`
  с зеркала GitHub Releases проекта `sapics/ip-location-db`. Официальный сайт DB-IP с
  сервера режется (Cloudflare), MaxMind закрыт для РФ.
- Схема записи у зеркала своя: `city`, `state1`, `country_code`, `latitude`, `longitude`.
- Чтение — npm `maxmind` с `watchForUpdates`; путь — env `GEOIP_DIR` (по умолчанию
  `/srv/geoip`). Нет файлов — сервис работает, ручка отдаёт 204.
- Обновление — systemd-таймер на хосте раз в месяц: скачать во временный файл в том же
  каталоге, проверить размер, `mv -f` на место. Каталог `/opt/gmd/data/geoip` монтируется
  в backend `:ro` целиком (не файл: после `mv` bind-mount файла видел бы старый inode).
- Атрибуция «IP Geolocation by DB-IP» со ссылкой на db-ip.com — в подписи карты, когда
  центр взят по IP.
- Точность проверена на реальных адресах семьи: домашний провайдер — верный город,
  мобильный интернет и МТС — соседние города за сотни км. Поэтому IP — только запасной
  вариант.

### 1.6 Кабинет (`/cabinet/zones`)

- **Центр карты** по цепочке: зоны + последние точки детей (`fitBounds` через `useMap`;
  проп `bounds` у `MapContainer` в react-leaflet 5 игнорируется при заданных
  `center`/`zoom`) → запомненный вид (`localStorage`, ключ с `userId`) → город по IP
  (`/geo/ip-center`, подпись DB-IP) → Москва.
- **Кнопка «Где я»** — геолокация браузера только по нажатию, со своим обработчиком ошибки.
- **Дети на карте** (маркер с именем) и **«кто сейчас в зоне»** в списке зон (по `states`).
- **«Создать зону здесь»** от ребёнка — редактор открывается с центром в его точке.
- **Удаление зоны** с подтверждением.
- **Редактор**: радиус 100..5000 (по умолчанию 150), карта переезжает к выбранному адресу,
  геокодер со смещением к центру карты (`ll` + `spn`), «Все дети, включая будущих»
  (по умолчанию включено), новая зона открывается в текущем виде карты, а не в Москве.
- **Лента**: дата и время по `recordedAt`, фильтры по ребёнку и зоне, «Показать ещё»
  (курсор), длительность пребывания у выхода, нейтральные по роду формулировки.
- Русские тексты ошибок по `code`; тумблер «Показывать геозоны» запоминается;
  токены темы вместо `zinc`/`red`/`green`.

### 1.7 Проверка

- unit: классификация (внутри / снаружи / неясно, `acc`), гистерезис без сброса
  `pending`, молчаливое начальное состояние, `durationSec`, приватные IP, курсор ленты.
- e2e (testcontainers): ложного «входа» нет, если ребёнок уже внутри новой зоны;
  правка радиуса пересчитывает состояние без события; «все дети»; курсор при равном
  `recordedAt`; `/family/locations/latest` без outlier.
- Прод: `/api/geo/ip-center` из браузера; тестовая зона вокруг текущей точки ребёнка —
  без ложного «входа»; лента; удаление тестовой зоны.

## Этап 2 «Умные уведомления» (0.65.0)

### 2.1 Что получает родитель

- **Личные настройки у каждого родителя**: пользователь × зона × ребёнок — «приход»,
  «уход», «не пришёл к сроку». Нет строки — всё включено. Второй родитель семьи свои
  настройки видит и меняет отдельно.
- **Расписание зоны** (общее на семью): дни недели + окно «с–до», переход через полночь
  разрешён. Вне окна push о приходе и уходе не шлётся, событие в ленте остаётся. Нет
  расписания — уведомления круглосуточно.
- **«Не пришёл к сроку»** (общее на семью): срок (время дня), дни недели, запас
  0..120 мин (по умолчанию 10). Проверяется для всех детей зоны.
- Часовой пояс зоны — IANA, из браузера родителя при сохранении
  (`Intl.DateTimeFormat().resolvedOptions().timeZone`). Обязателен, если задано расписание
  или срок. `ChildDevice.timezone` новые телефоны больше не присылают, по координатам
  пояс не вычисляем (лишняя библиотека ради семьи в одном поясе).

Срок задаётся на зону, а не на пару зона × ребёнок: у детей с разным временем обычно и
школы разные. Если понадобится разный срок в одной зоне — отдельная строка на ребёнка
в этапе 4 или позже.

### 2.2 Проверка «не пришёл»

Тик раз в минуту в backend (`setInterval`, как watchdog аудио), внутри транзакции под
`pg_try_advisory_xact_lock` — второй экземпляр или наложившийся тик просто пропускает
ход. В тестах (`NODE_ENV=test`) интервал не запускается, тик вызывается явно.

Для каждой зоны со сроком: местное время в поясе зоны; день недели в маске; минута
`m ∈ [срок + запас, срок + запас + 120)` (окно догоняния после рестарта). Для каждого
ребёнка зоны, если за (зона, ребёнок, местная дата) ещё нет проверки:

| Условие                                           | Вердикт   | Событие / push         |
| ------------------------------------------------- | --------- | ---------------------- |
| `ZoneState.isInside` или ожидание входа           | `arrived` | нет                    |
| вход в эту зону за местные сутки до срока + запас | `arrived` | нет                    |
| последняя хорошая точка свежее 20 мин             | `missed`  | `missed_arrival`, push |
| иначе (телефон молчит)                            | `no_data` | `no_data`, push        |

Проверка пишется в `zone_arrival_checks` с уникальным ключом
`(zoneId, childId, localDate)` — идемпотентность: повторный тик и рестарт не дублируют.
Push о «не пришёл» уходит родителям, у которых для пары включено «не пришёл к сроку»,
без учёта расписания зоны (срок — сам по себе окно).

### 2.3 Push новых типов и текущий APK родителя

Текущий APK родителя рисует только известные типы (`GEOFENCE_ENTER/EXIT`, `SOS`, …),
незнакомые выбрасывает. Мост до этапа 3: `GEOFENCE_MISSED` и `GEOFENCE_NO_DATA` уходят
с блоком FCM `notification` (заголовок + текст, канал `events`) — Android показывает его
сам, когда приложение свёрнуто. В этапе 3 APK научится рисовать эти типы сам, мост
убирается.

### 2.4 Модель и API

Миграция `20261002100000_zones_v2_notifications`:

- `zones`: `timezone TEXT`, `scheduleDaysMask INT`, `scheduleStartMin INT`,
  `scheduleEndMin INT`, `arrivalDeadlineMin INT`, `arrivalDaysMask INT`,
  `arrivalGraceMin INT NOT NULL DEFAULT 10` (все nullable, кроме запаса);
- `zone_notification_prefs (userId, zoneId, childId, onEntry, onExit, onMissedArrival)`,
  уникальность `(userId, zoneId, childId)`, каскад по всем трём;
- `zone_arrival_checks (zoneId, childId, localDate, verdict, createdAt)`, уникальность
  `(zoneId, childId, localDate)`;
- `ZoneEventType += missed_arrival, no_data`.

`POST /zones`, `PATCH /zones/:id` — дополнительно:

```jsonc
{
  "timezone": "Asia/Vladivostok", // обязателен при schedule/arrival
  "schedule": { "daysMask": 31, "startMin": 480, "endMin": 900 }, // или null — снять
  "arrival": { "deadlineMin": 510, "daysMask": 31, "graceMin": 10 }, // или null — снять
}
```

`daysMask`: бит 0 — понедельник … бит 6 — воскресенье (1..127). `startMin ≠ endMin`.
Ошибки: `400 timezone_required`, `400 invalid_timezone`.

`ZoneDto` — дополнительно `timezone`, `schedule`, `arrival` и `myPrefs` — личные настройки
текущего пользователя по всем детям зоны (с заполненными значениями по умолчанию):

```jsonc
"myPrefs": [{ "childId": "…", "onEntry": true, "onExit": true, "onMissedArrival": true }]
```

`PUT /zones/:id/my-notifications` — `{ "items": [{ childId, onEntry, onExit, onMissedArrival }] }`
→ `{ "items": [...] }` (итоговые настройки текущего пользователя). Ребёнок не из зоны — 404.

`ZoneEventDto.type` — `entry | exit | missed_arrival | no_data`; у `missed_arrival` и
`no_data` координаты — последняя точка ребёнка (или центр зоны, если точек нет).

### 2.5 Кабинет

- Редактор зоны: блок «Расписание уведомлений» (дни + с/до), блок «Не пришёл к сроку»
  (время, дни, запас), пояс берётся из браузера молча и показывается подписью.
- Блок «Мои уведомления» в зоне: по каждому ребёнку три переключателя, подпись «только
  для вас — у другого родителя свои».
- Список зон: значки «по расписанию» и «срок 08:30».
- Лента: «Аня — не пришла к 08:30 в «Школа»» нейтрально по роду («не пришёл(а)»),
  «нет данных от телефона к сроку»; фильтр по типу не нужен.

### 2.6 Проверка

- unit: окно расписания (через полночь), вердикты тика, идемпотентность, фильтр push по
  личным настройкам и расписанию.
- e2e: срок наступил, ребёнок вне зоны со свежей точкой → `missed_arrival` один раз;
  ребёнок внутри → ничего; телефон молчит → `no_data`; личные настройки двух родителей;
  расписание гасит push, но не событие.
- Прод: тестовая зона со сроком «через 2 минуты» вне места ребёнка → событие в ленте и
  push на телефон родителя (свёрнутое приложение); удалить зону.

## Этап 3 «Геозоны в приложении родителя» (0.66.0)

### 3.1 Экраны (Flutter, `lib/features/zones/`)

- **Геозоны** (`/home/zones`, вход из шапки главного экрана и с экрана ребёнка): карта
  (`flutter_map` + `CircleLayer` зон + маркеры детей), список зон с «кто сейчас внутри»,
  значками расписания и срока, кнопки «Новая зона» и «События».
- **Редактор** (`/home/zones/new?lat=&lon=`, `/home/zones/:id/edit`): пин по центру карты
  (центр зоны = центр карты, перетаскиваемого маркера у `flutter_map` нет), радиус
  100..5000 (по умолчанию 150), название, цвет, иконка, «Все дети, включая будущих»,
  расписание и срок — как в кабинете. Удаление с подтверждением.
- **Мои уведомления** — в карточке зоны: по каждому ребёнку «приход», «уход», «не пришёл».
- **Лента** (`/home/zones/events?zoneId=&childId=`): фильтры, «показать ещё» по курсору,
  все четыре типа событий.
- **Карта ребёнка**: круги его зон.
- **Центр карты** — та же цепочка, что в кабинете: зоны и дети → последний вид
  (локально) → `/geo/ip-center` → Москва. **«Где я»** — `geolocator` +
  `ACCESS_COARSE_LOCATION`, разрешение спрашиваем только по нажатию.
- Пояс для расписания и срока — `TimeZone.getDefault().id` через MethodChannel
  (`pro.periscop.parent/device`, метод `timeZone`), без нового пакета.
- Грабли карт из прошлых экранов: `_tileGen` для пересоздания `TileLayer`,
  `Stack(fit: StackFit.expand)`, Impeller выключен в манифесте.

### 3.2 Push

- `ParentFirebaseMessagingService` рисует `GEOFENCE_MISSED` и `GEOFENCE_NO_DATA` сам.
- id уведомления для `GEOFENCE_*` — по паре ребёнок × зона (раньше `hash(type:childId)`:
  события двух зон затирали друг друга); `requestCode` у `PendingIntent` — тот же id,
  иначе extras последнего уведомления достаются всем.
- Тап по уведомлению → `MainActivity` (extras `fcm_type`, `deeplink_child_id`, `zone_id`)
  → MethodChannel `pro.periscop.parent/push` (`getInitialPush` при старте, `onPush` из
  `onNewIntent`) → Dart открывает ленту зоны (`GEOFENCE_*`) или экран ребёнка (остальные).
- **Мост этапа 2 становится условным**: блок FCM `notification` для `GEOFENCE_MISSED` и
  `GEOFENCE_NO_DATA` backend шлёт только устройствам с `appVersion` ниже 0.66.0 —
  иначе Android рисовал бы уведомление сам и `onMessageReceived` в фоне не вызывался.

- Нативный экран: список + карта (`flutter_map` `CircleLayer`, пин по центру вместо
  перетаскиваемого маркера) + создание и правка + лента.
- Переход из push (`onNewIntent` + MethodChannel); id уведомления по паре ребёнок × зона
  вместо `hash(type:childId)`; новые типы push этапа 2.
- «Где я» — `geolocator` + `ACCESS_COARSE_LOCATION` только по нажатию; центр по той же
  цепочке через `/geo/ip-center`; круги зон на карте ребёнка.
- Проверка на реальном телефоне обязательна.
