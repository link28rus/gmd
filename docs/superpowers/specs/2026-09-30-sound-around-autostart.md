# «Звук вокруг» после перезагрузки: автозапуск микрофона без участия ребёнка

**Дата:** 2026-09-30
**Статус:** **выпущено в v0.68.0** (коммит ce15ae6, APK на проде, endpoint
проверен). Механизм подтверждён на эмуляторе Android 15; онбординг-разрешение
добавлено обязательным шагом мастера. Осталось: проверка на реальном
MIUI/HyperOS телефоне ребёнка после того, как там будет выдано разрешение
«поверх других приложений».
**Затрагивает:** `apps/mobile-child`

## Задача

После перезагрузки телефона ребёнка (и после тихого самообновления) «Звук
вокруг» не работает, пока ребёнок сам не коснётся приложения или уведомления.
Родитель нажимает «Слушать» и получает «Телефон ребёнка не дал включить
микрофон». Требование: должно подниматься само, ребёнка не задействовать — «как
у конкурентов».

## Корень проблемы

Android 14 ввёл гейт **while-in-use (WIU)**. Служба переднего плана с типом
`microphone`, запущенная пока приложение в фоне, доступ к микрофону не получает.
`BOOT_COMPLETED` / `MY_PACKAGE_REPLACED` разрешают лишь _запустить_ службу, но
микрофон не дают. Обычные исключения фонового старта (high-priority push,
отключённая оптимизация батареи, companion device) гейт WIU не снимают.

## Тупиковая ветка: `targetSdk 33` (проверено и отвергнуто)

Гипотеза: гейт применяется только при `targetSdk 34+`, значит понижение до 33
вернёт автозапуск. **Опровергнуто эмпирически** на эмуляторах Android 15 (API 35)
и Android 16 (API 36): при `targetSdk 33` `startForeground(type=MICROPHONE)` из
`BootReceiver` проходит без `SecurityException`, но система молча снимает право —
права процесса `caps=---NFU-` вместо `LCMNFUAT`, в журнале «Foreground service
started from background can not have location/camera/microphone access». Служба
«работает» и пишет тишину, `micReady` рапортует `true`, родитель не видит даже
честной ошибки — это **хуже** исходного. `targetSdk` оставлен 34.

## Найденный механизм: разрешение «поверх других приложений»

Ключ — точная формулировка Android про то, кто получает WIU
([bg-audio, Android 17](https://developer.android.com/about/versions/17/changes/bg-audio)):

> **Standard FGS**: Services started while the app is visible **or granted
> background activity launch capability** are granted WIU access.

И список условий фонового запуска активности
([background-starts](https://developer.android.com/guide/components/activities/background-starts)):
среди них — **`SYSTEM_ALERT_WINDOW`** («Отображение поверх других приложений»).

Отсюда рабочая цепочка, не требующая участия ребёнка на каждой перезагрузке:

1. Ребёнок один раз при настройке выдаёт «поверх других приложений»
   (`SYSTEM_ALERT_WINDOW`).
2. Это даёт приложению **background-activity-launch capability**.
3. После перезагрузки `BootReceiver` автоматически запускает прозрачную
   `MicWakeActivity` (уже существует).
4. Видимая на долю секунды активность = приложение на переднем плане → **WIU
   выдаётся** → prewarm службы микрофона проходит.

Половина цепочки — «видимая активность → WIU» — **уже подтверждена в проде**:
это ровно механизм v0.62.0, где ту же `MicWakeActivity` открывает тап ребёнка по
уведомлению. Новое здесь — запускать её автоматически, без тапа, за счёт
`SYSTEM_ALERT_WINDOW`. Это, с высокой вероятностью, и есть «из коробки» у
конкурентов: приложения этого класса штатно просят «поверх других приложений».

Заметка про версии: список WIU-исключений в
[restrictions-bg-start](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)
для Android 14 явно не называет `SYSTEM_ALERT_WINDOW`. Поэтому надёжный путь —
не «служба получает WIU напрямую от разрешения», а «разрешение позволяет
запустить **видимую активность**, а уже видимость приложения даёт WIU на всех
версиях». Реализация запускает настоящую активность, а не пытается стартовать
службу из фона.

## Что реализовано (кандидат, uncommitted)

- `AndroidManifest.xml` — возвращён `SYSTEM_ALERT_WINDOW` (был убран в v0.58.0
  вместе с блокировкой приложений).
- `BootReceiver.kt` — если `Settings.canDrawOverlays(context)`, автоматически
  запускает `MicWakeActivity` (новый источник `FROM_BOOT`); иначе — прежний путь.
- `MicWakeActivity.kt` — константа `FROM_BOOT`.

## Что НЕ доделано

- **Выдача разрешения ребёнком.** Нужен шаг онбординга/экрана настройки: запрос
  «поверх других приложений» (`Settings.ACTION_MANAGE_OVERLAY_PERMISSION`) с
  человеческим объяснением. Без него разрешения на устройстве нет и авто-запуск
  не сработает (будет откат на уведомление).
- **Само-исцеление по запросу родителя.** Кроме загрузки, ту же авто-активацию
  (`canDrawOverlays` → `MicWakeActivity`) стоит вызывать в обработчике
  `START_AUDIO`, когда prewarm холодный. Тогда даже если prewarm после
  перезагрузки не прошёл, первый же запрос родителя поднимет микрофон без
  действий ребёнка. Это более надёжная гарантия, чем расчёт только на
  `BOOT_COMPLETED`.
- **`MY_PACKAGE_REPLACED`** — тот же авто-запуск после самообновления (та же
  ветка `BootReceiver`, уже покрыта, отдельно проверить).

## Статус проверки

- ✅ Корень проблемы и провал `targetSdk 33` — подтверждено на эмуляторах.
- ✅ «Видимая активность → WIU» — подтверждено в проде (v0.62.0).
- ✅ **Полная цепочка авто-запуска при загрузке — ПОДТВЕРЖДЕНА на эмуляторе
  Android 15** (свежий cold-boot, release-сборка `targetSdk 34`, разрешения
  выданы, `SYSTEM_ALERT_WINDOW` = allow). Журнал перезагрузки:

  ```
  [boot]  BootReceiver: received BOOT_COMPLETED
  [sound] BootReceiver(BOOT_COMPLETED): MicWakeActivity авто-запуск (право overlay есть)
  [sound] prewarm: startForeground FAILED (need foreground caller): SecurityException  ← прямой из фона, ожидаемо
  [sound] MicWakeActivity: opened from=boot importance=100/foreground → prewarm       ← активность стала видимой
  [sound] prewarm: startForeground(type=MICROPHONE) OK                                 ← микрофон выдан
  [sound] micReady false→true (prewarm OK)
  ```

  Права процесса после: `curCapability=L-MNFUA` — буква **`M` (микрофон)
  присутствует** (против `---NFU-` у провального `targetSdk 33`) и **сохраняется**
  после закрытия активности, когда процесс уже в фоне (`curProcState=4`=FGS).
  `MicWakeActivity` мелькнула и закрылась, фокус вернулся на лаунчер. Ребёнок
  ничего не делал. Всё заняло ~1.7 с от загрузки.

- Грабли эмулятора (не относятся к реальным телефонам): (1) после серии
  перезагрузок Android 15 перестаёт доставлять `BOOT_COMPLETED` — нужен свежий
  cold-boot (`emulator -wipe-data`); (2) `SYSTEM_ALERT_WINDOW` даётся только через
  `appops set --user 0 … allow`; (3) на `targetSdk 34` `LocationForegroundService`
  при загрузке падает с `SecurityException`, если не выдан
  `ACCESS_BACKGROUND_LOCATION` (на телефоне ребёнка выдан — там этого нет).

**Осталось до прода:** (а) онбординг-шаг с запросом «поверх других приложений»
(без него разрешения нет и авто-запуск не сработает); (б) проверка на реальном
MIUI/HyperOS — у оболочек Xiaomi своя политика overlay, механизм Android
подтверждён, но фактическое поведение оболочки надо увидеть.

## Отвергнутые варианты

| Вариант                                                    | Почему нет                                                                                    |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `targetSdk 33`                                             | проверено: микрофон молча отбирается (`caps=---NFU-`), хуже исходного                         |
| High-priority push / отключение батареи / companion device | снимают запрет на _запуск_ службы, но не входят в список WIU                                  |
| Полноэкранное уведомление                                  | на Android 14 для звонков и будильников, требует отдельного разрешения                        |
| Объявить `VoiceInteractionService`                         | роль голосового ассистента; занимать её ради фонового микрофона — злоупотребление             |
| Тип службы `specialUse`                                    | снимает запрет запуска из `BOOT_COMPLETED`, но микрофон (WIU) всё равно не даёт               |
| Режим владельца устройства                                 | работает, но требует заводского сброса телефона — запасной путь, если overlay не подтвердится |
