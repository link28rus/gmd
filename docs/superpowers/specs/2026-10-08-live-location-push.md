# Карта ребёнка у родителя в реальном времени (v0.69.0)

**Статус:** выпущено в v0.69.0.

## Задача

Экран ребёнка в приложении родителя должен показывать новую точку сразу, как она пришла
на сервер, а не раз в 30 секунд (опрос из v0.68.3).

## Решение

Тихий FCM data-push `LOCATION_UPDATED` **только родителям, у которых экран ребёнка открыт**.

1. Экран при открытии и при каждом обновлении (опрос раз в 30 с, push, ручное «Обновить»)
   вызывает `PUT /children/:id/location/watch` → 204. Отметка живёт 90 с
   (`WATCH_TTL_SEC`): Redis sorted set `loc-watch:<childId>`, member = userId,
   score = момент истечения в мс.
2. `LocationsService.ingestBatch`: если вставилась хотя бы одна точка — после пересчёта
   поездок (иначе родитель перезапросит старый трек) вызывается
   `LocationWatchService.notifyNewPoints(childId, familyId)`.
3. `notifyNewPoints`: список смотрящих → троттлинг `SET loc-push:<childId> NX EX 3` →
   устройства родителей семьи, отфильтрованные по смотрящим userId →
   `FcmService.sendHybridToToken` с `data: {type: LOCATION_UPDATED, childId}`,
   `priority: normal`, `ttlSec: 60`, `collapseKey: loc-<childId>`, без `notification`.
   Ошибки глотаются — экран всё равно обновится опросом.
4. Приложение родителя: `ParentFirebaseMessagingService` на `LOCATION_UPDATED`
   уведомление не показывает, а передаёт `childId` в Dart через канал
   `pro.periscop.parent/live` (если движок Flutter жив). `LiveLocationPush.childUpdates`
   → экран ребёнка вызывает `_refresh(manual: false)`. Push, пришедший во время запроса,
   ставит повтор (`_refreshAgain`). В фоне событие игнорируется.

## Почему так

- **Не на каждую точку всем родителям.** Телефон ребёнка шлёт точки весь день; push на
  каждую будил бы телефоны родителей без нужды, а Android понижает приоритет
  high-priority сообщениям без видимого уведомления.
- **`priority: normal`.** Экран открыт — телефон не спит, будить из Doze не нужно.
- **Отдельный канал `/live`**, а не `/push`: тот отвечает за переходы по тапу на
  уведомление, смешивать с тихими событиями — риск случайной навигации.
- **Не WebSocket родителя.** Отдельный сокет родителя — больше кода и состояния
  (переподключения, авторизация); FCM уже работает и доставляет за секунды.
- **Опрос 30 с остаётся**: запасной путь при сбое FCM и продление отметки «смотрю».

## Совместимость

Старые APK родителя (до v0.69.0) не вызывают `watch` — им push не уходит. Если всё же
придёт `LOCATION_UPDATED`, старый `render()` вернёт `null` и уведомления не будет.
Новый APK со старым сервером: `watch` → 404, ошибка глотается, работает опрос.
