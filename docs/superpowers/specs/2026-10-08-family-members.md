# Участники семьи: приглашение взрослого, удаление, выход, передача прав (v0.71.0)

## Решения пользователя (2026-10-08)

- Приглашённый — **полноправный родитель** (роль `parent`): видит и делает всё то же, что владелец
  (дети, карта, геозоны, звук вокруг, SOS, push). Только **владелец** (`owner`) переименовывает семью,
  приглашает, удаляет участников и передаёт права.
- Приглашение — **ссылка с кодом** (`{WEB_BASE_URL}/join/<CODE>`, 8 символов Crockford base32,
  одноразовое, живёт 7 дней). Отправляет сам владелец (мессенджер, «Поделиться»), писем сервер не шлёт.
- **Один человек — одна семья.** Принять приглашение можно, только если в текущей семье человека нет
  детей и других взрослых: такая пустая семья растворяется (soft-delete), человек переходит в новую.
  Иначе — понятная ошибка «сначала выйдите / передайте права / удалите детей».
- Делаем веб-кабинет + приложение родителя, удаление и выход из семьи, передачу прав владельца.

## Инвариант

У каждого живого пользователя ровно одно членство. Выход или удаление из семьи → для человека
сразу создаётся новая пустая семья, где он владелец (как при регистрации). Поэтому код, который
берёт «первое членство» (логин, refresh, `/me`), продолжает работать. Все выборки членства —
`orderBy createdAt asc`.

## Модель

`family_invites` (отдельно от детских `invites` — у них обязателен `childId`):

| поле         | тип                           | смысл                                    |
| ------------ | ----------------------------- | ---------------------------------------- |
| id           | cuid                          |                                          |
| familyId     | FK → families, cascade        |                                          |
| code         | unique                        | 8 символов Crockford base32              |
| createdById  | FK → users, cascade           | кто пригласил                            |
| expiresAt    | timestamp                     | создание + 7 дней                        |
| acceptedAt   | nullable                      | момент принятия                          |
| acceptedById | nullable FK → users, set null | кто принял                               |
| revokedAt    | nullable                      | отозвано владельцем / семья растворилась |
| createdAt    |                               |                                          |

Активное приглашение: `acceptedAt IS NULL AND revokedAt IS NULL AND expiresAt > now()`.
Не больше 10 активных на семью.

## API (backend, всё под JWT; снаружи `/api/family/*` Caddy шлёт прямо в backend)

| метод и путь                                  | кто        | ответ / ошибки                                                                                                     |
| --------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------ |
| `GET /family/members`                         | любой член | `{ family:{id,name}, myRole, members:[{userId,displayName,email,role,joinedAt,isMe}] }` (владелец первым)          |
| `POST /family/member-invites`                 | owner      | 201 `{ invite:{id,code,url,expiresAt,createdAt} }`; 403 `forbidden`; 409 `too_many_invites`                        |
| `GET /family/member-invites`                  | owner      | `{ invites:[…активные] }`                                                                                          |
| `DELETE /family/member-invites/:id`           | owner      | 204; 404 `not_found`                                                                                               |
| `GET /family/member-invites/preview?code=X`   | любой      | `{ family:{name}, invitedBy, expiresAt, canJoin, reason? }`; 404 `invite_invalid`                                  |
| `POST /family/member-invites/accept` `{code}` | любой      | 200 `{ family:{id,name}, role:'parent' }`; 404 `invite_invalid`; 409 `already_member` / `current_family_not_empty` |
| `DELETE /family/members/:userId`              | owner      | 204; 400 `cannot_remove_self`; 404 `not_found`                                                                     |
| `POST /family/leave`                          | parent     | 200 `{ family:{id,name} }` (новая пустая семья); 409 `owner_must_transfer`                                         |
| `POST /family/transfer-ownership` `{userId}`  | owner      | 204; 400 `cannot_transfer_to_self`; 404 `not_found`                                                                |
| `PATCH /family/:id` `{name}` (было)           | owner      | без изменений                                                                                                      |

`reason` в preview и тело 409 `current_family_not_empty`: `already_member` | `has_children` |
`has_members` (в текущей семье есть другие взрослые). Детали: `{ currentFamilyName, children, members }`.

Роль проверяется по БД, не по JWT.

## Устаревшие токены

JWT несёт `familyId` и живёт 15 минут, а guard в БД не ходит. После смены членства (принял, вышел,
удалён, передал права) backend пишет в Redis `auth:stale:<userId>` = текущее время (мс, TTL 16 мин).
`JwtAuthGuard` отвечает 401 `token_stale` на токен, выпущенный раньше этой отметки (своя claim
`iatMs`: стандартный `iat` посекундный, а refresh сразу после смены членства часто попадает в ту же
секунду; у старых токенов без `iatMs` — `iat × 1000`) → клиенты уже умеют
на 401 делать refresh, refresh берёт актуальное членство. Удалённый участник теряет доступ к
данным семьи сразу, а не через 15 минут. Redis недоступен → guard пропускает (fail-open, лог).

После принятия, выхода или передачи клиент сам делает refresh и перезагружает данные.

## Попутные исправления

- `issueTokens` писал в JWT `role: 'owner'` всем — теперь реальная роль из членства.
- Логин/OTP/подтверждение email брали `memberships[0]` без сортировки — теперь `createdAt asc`.
- `DELETE /me` не трогал членство: удалённый оставался в семье и получал push. Теперь общая с
  админкой логика (`detachUserFromFamilies`): владелец с другими взрослыми → права самому раннему
  участнику; один в семье → семья с детьми в soft-delete; участник → просто убрать членство.
- При удалении/выходе удаляются личные настройки уведомлений геозон (`zone_notification_prefs`)
  человека по детям прежней семьи.

## Клиенты

- **Web:** `/cabinet/family` — название (владелец меняет), участники с ролями, «Пригласить»
  (ссылка + код, копировать), активные приглашения с отзывом, «Удалить», «Сделать владельцем»,
  «Выйти из семьи», «Ввести код приглашения». `/join/[code]` — превью и «Присоединиться»;
  без входа — код запоминается (localStorage) и после входа/регистрации кабинет возвращает на `/join`.
- **mobile-parent:** экран «Семья» из меню с тем же набором; приглашение — системное «Поделиться»;
  «Ввести код приглашения». Глубоких ссылок нет: ссылка открывается в браузере (web-флоу) или код
  вводится вручную.

## v0.72.0: владелец заводит участника сам (email + пароль)

Решения пользователя (2026-10-08): без письма и подтверждения email; пароль владелец вводит сам
или берёт из генератора и передаёт человеку; ФИО указывается сразу; аккаунт сразу подключается к
семье владельца (без приглашения); форма и в кабинете, и в приложении.

- `POST /family/members` `{ email, lastName, firstName, middleName?, password }` — только owner,
  201 `{ member }` (как в `GET /family/members`). ФИО и правила — как у регистрации: фамилия и имя
  обязательны, отчество по желанию; пароль 8–128.
- Создаётся пользователь с `emailVerifiedAt = now()` и членством `parent` в семье владельца — входит
  паролем или кодом из письма сразу.
- Email уже есть в системе (в любом состоянии) → 409 `email_taken` «отправьте приглашение»:
  чужой аккаунт так не забрать и пароль ему не сменить.
- **Политику участник принимает сам**: `acceptedPrivacyPolicyVersion = null`. Пока не принял — чтение
  работает, изменения отвечают 403 `consent_required`. В вебе — существующий баннер согласия; в
  приложении родителя — экран принятия после входа (`GET /me` → `requiresConsent`,
  `POST /me/consent { documents: ['PRIVACY_POLICY','TERMS_OF_USE'] }`).
- Участник меняет пароль сам на странице «Пароль».
