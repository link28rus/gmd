# Трек ребёнка без интернета (v0.59.0)

**Дата:** 2026-09-28
**Статус:** реализовано в v0.59.0
**Заменяет:** раздел «LocationIngestor / Параметры» в
[2026-04-20-gmd-phase3-mobile-child-design.md](2026-04-20-gmd-phase3-mobile-child-design.md)

## Проблема

Поездка 28.09 рисовалась на карте прямой линией через поля. Причина — на телефоне
ребёнка, а не на сервере:

1. Очередь `pending_locations` в Drift отбирала только точки с `upload_attempts < 5`.
   Каждая неудачная отправка увеличивала счётчик у всей пачки, а без сети flush
   шёл на каждой новой точке — через ~2 минуты офлайна точки «замерзали» и больше
   никогда не уходили, хотя физически лежали в базе.
2. Сервер принимал точки не старше 24 часов (исправлено в v0.58.1 — 7 суток).
3. Карта соединяла соседние точки линией независимо от разрыва во времени.

## Решение

### Телефон ребёнка — очередь (`LocationIngestor`, Dart)

- Точка из очереди не выбрасывается из-за числа неудачных попыток. Выход из
  очереди только три: сервер принял, сервер отверг именно эту точку (400 после
  деления пачки пополам до одной точки), точка старше 7 суток / очередь больше
  50 000 точек (удаляются самые старые).
- Миграция схемы 5: `upload_attempts = 0` для всех строк — точки, «замёрзшие» у
  прошлых версий, уходят после обновления. Индекс по `recorded_at`.
- Выборка — самые старые первыми (`ORDER BY recorded_at, id`), пачка до 500.
- Без сети — пауза между попытками 15 с → 30 с → 1 мин → 2 мин → 5 мин; в паузе
  новая точка только ложится в очередь, в сеть не ходим. Сеть вернулась
  (`ConnectivityManager`, INTERNET + VALIDATED) → пауза сбрасывается, flush сразу.
- Разгрузка хвоста: до 8 пачек за проход (4000 точек), затем 30 с паузы — чтобы
  не упереться в лимит 20 запросов в минуту на устройство.
- 413 → пачка уменьшается вдвое и отправляется частями; 429 и 5xx → пауза.
- Одна отправка одновременно (single-flight); команды опрашиваются только после
  успешной доставки.
- `LocationPoint.toJson` не отправляет NaN/∞/отрицательную точность — такие
  значения сервер отверг бы всей пачкой.

### Телефон ребёнка — GPS (`LocationForegroundService`, Kotlin)

- Профиль ACTIVE (5 с / 10 м) без сети подписывается на FusedLocation с
  `setMaxUpdateDelayMillis(2 мин)`: чип GPS копит точки сам, процесс просыпается
  раз в 2 минуты, а не каждые 5 секунд. Точность трека та же.
- Сеть появилась (с задержкой 3 с, пропала — 20 с, чтобы не дёргаться на
  переключении Wi-Fi ↔ LTE) → `flushLocations()`, затем переподписка без пакетов.
- Heartbeat (AlarmManager 90 с) без сети в пакетном режиме пропускается.
- Дедупликация стоящего телефона считает время по времени фикса (`loc.time`), а
  не по времени доставки — иначе пачка из FusedLocation схлопывалась бы.

### Сервер

- `POST /child/locations`: пачка до 500 точек, окно приёма — 7 суток назад.
- Точки, которые старше последней сохранённой, не проверяются на «дрожание»
  относительно неё и не проходят через геозоны — состояние геозон уже сдвинуто
  более свежими точками. Геозоны считаются по точкам из хвоста, если они новее.
- Событие геозоны по точке старше 3 минут (`LATE_EVENT_MS`) уходит родителю с
  `data.delayed = '1'` и реальным `recordedAt`.

### Карта (web + приложение родителя)

Общий контракт разрыва: соседние точки дальше 300 м **и** дальше 5 минут друг от
друга — это «нет данных». Сплошная линия рисуется только внутри участков;
разрыв — тонкая серая пунктирная линия с подписью «нет данных · N мин» (минуты
округляются вниз). Реализации: `apps/web/lib/geo/track-gaps.ts`,
`apps/mobile-parent/lib/features/children/track_gaps.dart` — пороги и формат
подписи должны совпадать.

### Push родителю

`GeofenceNotificationText.kt`: для `delayed` — «Тимофей вошёл в зону «Школа» в 08:40 —
данные пришли с опозданием.»; если событие было в другой день — «27.09 в 08:40».

## Проверка

Эмулятор, сеть выключена ~9 минут во время движения по маршруту: старая версия
заморозила 28 точек (`upload_attempts = 5`); новая версия, установленная поверх
без сети, после миграции вернула их в очередь, FusedLocation отдавал пачки по
2 минуты, после включения сети сервер получил весь хвост, трек в БД без
разрывов, кроме 17 с на переустановку.

## Ограничения

- Если телефон выключен или сервис убит системой — точек нет, на карте будет
  «нет данных». Это честный разрыв, а не прямая через поля.
- Пакетный режим включается только в ACTIVE; в STILL интервал и так 60 с.
