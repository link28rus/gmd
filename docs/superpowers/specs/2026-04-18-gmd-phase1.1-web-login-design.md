# GMD Phase 1.1-web — Login + Cabinet MVP

**Дата:** 2026-04-18
**Фаза:** 1.1-web (UI для Phase 1.1 Auth)
**Зависит от:** Phase 1.1 backend (v0.4.0) — все auth endpoints готовы и протестированы.

## Цель

Родитель может в браузере пройти полный auth-flow (email → OTP → кабинет → logout) и увидеть свой профиль и имя семьи. MVP — для ручного тестирования backend через браузер и для демонстрации прогресса; дизайн-система и остальные экраны — следующие фазы.

## Scope

**Входит:**

- `/` — лендинг (уже есть) + кнопка «Войти».
- `/login` — двухстадийная форма (email → OTP).
- `/cabinet` — показ user + family, кнопка «Выйти».
- Next.js API-routes `/api/auth/{request-otp,verify-otp,refresh,logout}` и `/api/me` как прокси между клиентом и backend.
- Refresh-token в `httpOnly + Secure + SameSite=Lax` cookie `gmd_refresh`.
- Access-token в in-memory Zustand store.
- Silent refresh при mount `/cabinet`.
- Минималистичные Tailwind-стили без компонентной библиотеки.

**Не входит** (следующие фазы):

- Дизайн-система, shadcn/ui, иконки — Phase 1.1-web-v2 или отдельно.
- Настройки (rename family, change name, delete account) — Phase 1.1-web-v2.
- Страницы «Дети», «Карта», «SOS», dashboard — после соответствующих backend-фаз.
- Auto-refresh interceptor для произвольных protected endpoints — пока нужен только для `/me`, делаем на месте.
- Next.js middleware для redirect «unauthenticated → /login» — делаем серверным компонентом `/cabinet/page.tsx`.
- i18n — всё на русском hardcoded.
- Playwright / Vitest — не в scope 1.1-web.
- Server Actions — используем классические Route Handlers (чище для прокси-паттерна).

## Решения

| Вопрос                | Решение                                                            | Почему                                                                          |
| --------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| Scope                 | Только `/`, `/login`, `/cabinet`                                   | Минимум для ручного smoke всего backend auth-flow                               |
| Refresh-token storage | `httpOnly + Secure + SameSite=Lax` cookie через Next.js API-routes | Защита от XSS; CLAUDE.md фиксирует это решение; отсутствие CORS (single origin) |
| Access-token storage  | In-memory Zustand store                                            | Стандарт для SPA, утечка только на время сессии                                 |
| Backend URL           | Только server-side (`process.env.BACKEND_URL`)                     | Клиент не знает про backend, не нужен CORS                                      |
| Styling               | Минималистичный Tailwind без UI-kit                                | YAGNI, дизайн-система — отдельная фаза                                          |
| Тесты                 | Ручной smoke-чеклист в spec                                        | Playwright — Phase 5 по plan 0.1                                                |

### Data flow

```
Браузер                        Next.js (API route)              Backend (NestJS)
───────                        ───────────────────              ─────────────────
/login form
  POST /api/auth/request-otp →
                               fetch BACKEND_URL/auth/request-otp →
                                                                 202 Accepted
                               ← 202 (no body)
  ← 202

  POST /api/auth/verify-otp  →
                               fetch BACKEND_URL/auth/verify-otp →
                                                                 200 {access, refresh, user, family}
                               Set-Cookie: gmd_refresh=<refresh>
                               ← 200 {access, user, family}
  ← сохранить access в Zustand
  → router.push('/cabinet')

/cabinet (server component)
  1. если нет cookie → redirect '/login'
  2. render <CabinetClient/>

<CabinetClient> (client)
  1. mount → если store.accessToken пуст → POST /api/auth/refresh
     → получаем {access, user, family} → Zustand
  2. render user.email, family.name, кнопка «Выйти»

«Выйти»:
  POST /api/auth/logout →
                               backend logout + clear cookie
  → router.push('/')
```

### Next.js API-routes

Все запросы возвращают unified error format (совпадает с backend): `{ error: { code, message } }`.

**`POST /api/auth/request-otp`**:

```typescript
// body: { email }
const r = await backend('POST', '/auth/request-otp', req.body);
return NextResponse.json(r.body, { status: r.status });
```

**`POST /api/auth/verify-otp`**:

```typescript
// body: { email, code }
const r = await backend('POST', '/auth/verify-otp', req.body);
if (r.status !== 200) return NextResponse.json(r.body, { status: r.status });
const { accessToken, refreshToken, user, family } = r.body;
const res = NextResponse.json({ accessToken, user, family });
res.cookies.set('gmd_refresh', refreshToken, {
  httpOnly: true,
  secure: process.env.NODE_ENV === 'production',
  sameSite: 'lax',
  path: '/',
  maxAge: 60 * 60 * 24 * 30,
});
return res;
```

**`POST /api/auth/refresh`**:

```typescript
const old = req.cookies.get('gmd_refresh')?.value;
if (!old) return NextResponse.json({ error: { code: 'unauthenticated' } }, { status: 401 });
const r = await backend('POST', '/auth/refresh', { refreshToken: old });
if (r.status !== 200) {
  const res = NextResponse.json(r.body, { status: r.status });
  res.cookies.delete('gmd_refresh');
  return res;
}
const { accessToken, refreshToken } = r.body;
// также нам нужно отдать user+family — делаем GET /me с новым access
const me = await backend('GET', '/me', undefined, accessToken);
const res = NextResponse.json({ accessToken, ...(me.status === 200 ? me.body : {}) });
res.cookies.set('gmd_refresh', refreshToken, {
  /* same opts */
});
return res;
```

**`POST /api/auth/logout`**:

```typescript
const token = req.cookies.get('gmd_refresh')?.value;
if (token) await backend('POST', '/auth/logout', { refreshToken: token });
const res = new NextResponse(null, { status: 204 });
res.cookies.delete('gmd_refresh');
return res;
```

**`GET /api/me`**:

```typescript
const auth = req.headers.get('authorization');
if (!auth) return NextResponse.json({ error: { code: 'unauthorized' } }, { status: 401 });
const r = await backend('GET', '/me', undefined, auth.replace('Bearer ', ''));
return NextResponse.json(r.body, { status: r.status });
```

### `lib/backend.ts` (server-only fetch wrapper)

```typescript
const BACKEND_URL = process.env.BACKEND_URL ?? 'http://127.0.0.1:3001';

export async function backend(
  method: 'GET' | 'POST' | 'PATCH' | 'DELETE',
  path: string,
  body?: unknown,
  accessToken?: string,
): Promise<{ status: number; body: unknown }> {
  const res = await fetch(`${BACKEND_URL}${path}`, {
    method,
    headers: {
      'Content-Type': 'application/json',
      ...(accessToken ? { Authorization: `Bearer ${accessToken}` } : {}),
    },
    body: body !== undefined ? JSON.stringify(body) : undefined,
    cache: 'no-store',
  });
  const text = await res.text();
  const json = text ? JSON.parse(text) : null;
  return { status: res.status, body: json };
}
```

### `lib/auth-store.ts` (Zustand)

```typescript
import { create } from 'zustand';

interface User {
  id: string;
  email: string;
  name: string | null;
  locale: string;
}
interface Family {
  id: string;
  name: string;
}

interface AuthState {
  accessToken: string | null;
  user: User | null;
  family: Family | null;
  setAll: (s: { accessToken: string; user: User; family: Family }) => void;
  setAccess: (t: string) => void;
  clear: () => void;
}

export const useAuthStore = create<AuthState>((set) => ({
  accessToken: null,
  user: null,
  family: null,
  setAll: (s) => set(s),
  setAccess: (accessToken) => set({ accessToken }),
  clear: () => set({ accessToken: null, user: null, family: null }),
}));
```

### `lib/api-client.ts` (client fetch с auto-refresh)

```typescript
export async function apiFetch<T>(
  path: string,
  init?: RequestInit,
  accessToken?: string,
): Promise<{ status: number; data: T | null }> {
  const res = await fetch(path, {
    ...init,
    headers: {
      'Content-Type': 'application/json',
      ...(accessToken ? { Authorization: `Bearer ${accessToken}` } : {}),
      ...(init?.headers ?? {}),
    },
  });
  const text = await res.text();
  const data = text ? JSON.parse(text) : null;
  return { status: res.status, data };
}
```

_Auto-refresh инлайн в `CabinetClient` при 401, не усложняем._

### Страница `/login`

Client component. `useState`: `stage: 'email' | 'otp'`, `email`, `code`, `loading`, `error`.

- Стадия `email`: инпут + кнопка. При клике → `POST /api/auth/request-otp`. Успех → `stage='otp'`. Ошибка (429) → показать сообщение.
- Стадия `otp`: инпут code (6 цифр) + кнопка «Войти» + ссылка «Отправить код снова» → возврат в `stage='email'` со сбросом code. При клике «Войти» → `POST /api/auth/verify-otp`. Успех → `useAuthStore.setAll(...)` + `router.push('/cabinet')`. Ошибка → показать.

### Страница `/cabinet`

Server component:

```typescript
import { cookies } from 'next/headers';
import { redirect } from 'next/navigation';
import CabinetClient from './cabinet-client';

export default async function CabinetPage() {
  const cookieStore = await cookies();
  if (!cookieStore.get('gmd_refresh')) redirect('/login');
  return <CabinetClient />;
}
```

Client component `<CabinetClient>`:

- `useEffect` on mount → если `accessToken` пуст → `POST /api/auth/refresh` → `setAll(...)`. При 401 → `router.push('/login')`.
- Render: `<h1>Привет, {user.name ?? user.email}!</h1>`, `<p>Семья: {family.name}</p>`, `<button onClick={logout}>Выйти</button>`.
- `logout`: `POST /api/auth/logout` → `clear()` → `router.push('/')`.

## Ручной smoke-чеклист

1. `pnpm --filter @gmd/backend dev` + `pnpm stack:up` (MailHog, Postgres, Redis).
2. `pnpm --filter @gmd/web dev` → открыть `http://localhost:3003/`.
3. Нажать «Войти» → `/login`.
4. Ввести email `test@gmd.local` → «Получить код». Проверить 202.
5. Открыть `http://localhost:8025/` → скопировать 6-значный код из письма.
6. Ввести код → «Войти». Ожидаем редирект на `/cabinet` с «Привет, test@gmd.local!» и «Семья: Моя семья».
7. Открыть DevTools → Application → Cookies → увидеть `gmd_refresh` (httpOnly: ✓).
8. F5 на `/cabinet` → не должно выкинуть на `/login` (silent refresh сработал).
9. Нажать «Выйти» → редирект на `/`. Cookie очищен.
10. Открыть `/cabinet` без cookie → редирект на `/login` (серверный компонент).
11. Rate-limit: быстро 4 раза «Получить код» подряд → 4-й показывает «Слишком много попыток».
12. Неверный код → сообщение «Неверный код».
