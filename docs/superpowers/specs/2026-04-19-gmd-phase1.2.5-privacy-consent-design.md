# GMD Phase 1.2.5 — Политика конфиденциальности + согласия 152-ФЗ

**Дата:** 2026-04-19
**Фаза:** 1.2.5
**Зависит от:** Phase 1.1 (Auth, v0.4.0) — `User.acceptedPrivacyPolicyVersion` + `PRIVACY_POLICY_VERSION` env; Phase 1.2 (Child Invite, v0.5.0) — `POST /child/claim`.

## Цель

Привести GMD в соответствие с требованиями 152-ФЗ до добавления геолокации (Phase 2). Пользователь видит и принимает политику конфиденциальности на `/login` и при bump версии в кабинете. Факт согласия фиксируется в БД с version/timestamp/IP/UA. Ребёнок ≥14 лет: родитель подтверждает, что получил его согласие, при генерации invite.

## Scope

**Входит:**

- Markdown-тексты: `docs/legal/privacy-policy-v1.0.md`, `docs/legal/terms-of-use-v1.0.md` (я пишу под 152-ФЗ шаблон).
- Web-страницы `/privacy`, `/terms` — рендер MD через `next-mdx-remote` в React Server Components.
- Футер `Footer` со ссылками на `/privacy`, `/terms`, `/cabinet/changelog` (последняя — заготовка на v0.7+).
- Строка consent-hint под кнопкой на `/login`.
- Prisma-модель `ConsentRecord` + миграция `consent_record`.
- Backend `POST /me/consent` — фиксирует согласие (privacy/terms по version из env).
- Backend `GET /me` расширение — поле `requiresConsent: boolean`.
- Backend guard `ConsentRequiredGuard` — 403 `consent_required` на мутациях если юзер не принял текущую версию.
- Backend `POST /child/claim` — требует `consent14Plus: true` если возраст ребёнка ≥14 лет. Иначе 400 `consent14plus_required`.
- Web: чекбокс «Ребёнок старше 14 — я получил его согласие» в `InviteQrDialog` (показывается условно). При генерации invite родитель нажимает чекбокс → записываем в Child.
- Web-кабинет: non-dismissible баннер «Политика обновилась» → кнопка «Принять» → `POST /me/consent`. Все CRUD-кнопки disabled до принятия (UX, хотя backend тоже блокирует).
- Unit-тесты для guard и /me/consent; e2e — acceptance flow.
- CHANGELOG v0.7.0.

**Не входит** (следующие фазы):

- DSAR (экспорт/удаление по запросу) — Phase 1.3.
- Генерация hard-delete cron — Phase 1.3.
- Cookie-баннер GDPR-style — не нужен по 152-ФЗ.
- Многоязычность политики — только RU на MVP.
- Mobile-child согласие 14+ — Phase 3, пока через родителя.
- Рассылка email при bump версии — сделаем вместе с SMTP позже.

## Архитектура

### Данные (Prisma)

```prisma
enum ConsentSubjectType {
  USER
  CHILD
}

enum ConsentDocumentType {
  PRIVACY_POLICY
  TERMS_OF_USE
  CHILD_14PLUS
}

model ConsentRecord {
  id            String              @id @default(cuid())
  subjectType   ConsentSubjectType
  userId        String?             // если subjectType=USER или subjectType=CHILD (родитель, который подтвердил)
  childId       String?             // если subjectType=CHILD
  documentType  ConsentDocumentType
  version       String              // '1.0'
  acceptedAt    DateTime            @default(now())
  ip            String?             // IPv4/6, 45 chars max
  userAgent     String?             // truncated до 500 chars

  user  User?  @relation(fields: [userId], references: [id], onDelete: Cascade)
  child Child? @relation(fields: [childId], references: [id], onDelete: Cascade)

  @@index([userId, documentType, acceptedAt])
  @@index([childId, documentType, acceptedAt])
  @@index([subjectType, documentType, version])
  @@map("consent_records")
}
```

User и Child получают обратные relations: `consents ConsentRecord[]`.

`User.acceptedPrivacyPolicyVersion` **остаётся** — денормализация для быстрой проверки в guard (избегаем JOIN на каждом request). Обновляется вместе с INSERT `ConsentRecord`.

**Миграция:** `prisma migrate dev --name consent_record`.

```
  Ответ (расширен):

```

```
  body: { code, deviceName?, osVersion?, appVersion?, consent14Plus?: boolean }
```

**Footer:** sticky footer на всех страницах (root layout `app/layout.tsx`), строка: `© 2026 GMD · [Политика] · [Условия]`.

**Login consent hint:** строка под кнопкой:

> «Нажимая «Отправить код», вы принимаете [Политику конфиденциальности](/privacy) и [Условия использования](/terms).»

**ConsentBanner (cabinet):** рендерится только если `me.requiresConsent === true`. Не-dismissible, вверху страницы:

```

│ ⚠ Политика конфиденциальности обновлена                │
│ Чтобы продолжить пользоваться GMD, прочитайте [новую    │
│ версию] и подтвердите согласие.                         │
│                                                         │
│              [ Прочитал и согласен ]                    │
└─────────────────────────────────────────────────────────┘
```

Кнопка → `POST /api/me/consent` body `{ documents: ['PRIVACY_POLICY','TERMS_OF_USE'] }` → invalidate `['me']` → банер исчезает.

**InviteQrDialog — 14+ checkbox:**

Возраст вычисляется из `child.dateOfBirth` (если null — не показываем чекбокс). Если ≥14:

```
□ Ребёнок старше 14 лет, и я получил его согласие на передачу
  геолокации и связанных данных (ст. 9 ФЗ-152).
```

Кнопка «Сгенерировать код» disabled пока чекбокс не отмечен. При POST `/api/children/:id/invites` клиент передаёт `consent14Plus: true` в body. Родитель в момент клика = событие consent (backend пишет `ConsentRecord` при успешном claim, не на invite; invite только сохраняет намерение в памяти web).

Альтернатива: записывать consent на claim — логичнее, потому что именно там child связывается с устройством. Финальный вариант: **checkbox на invite + body claim** — и `consent14Plus` проходит через invite payload. Реализация: invite body `{ consent14Plus?: boolean }`, сохраняется в `Invite.consent14Plus` (nullable bool). При claim читается. Если `consent14Plus !== true` и возраст ≥14 → 400.

Для упрощения — пойдём проще: `consent14Plus` передаёт **клиент ребёнка** в `/child/claim` body. Родитель ничего дополнительно не вводит. При сборке UI на MVP нет клиента ребёнка → smoke через curl. Чекбокс родителя — задел на Phase 3, но **на Phase 1.2.5 его НЕ делаем** (упрощение). Backend-требование `consent14Plus` в claim body при возрасте ≥14 — **включаем**, но на web НЕ добавляем (зачем — child-клиент присылает из своего UI).

**Итоговое упрощение scope:** UI-чекбокс 14+ в InviteQrDialog — **убираем** из Phase 1.2.5. Оставляем только backend-требование. Комментарий в spec отметит, что UI добавится в Phase 3 (mobile-child). Если потребуется для web-curl-smoke — просто передать `consent14Plus: true` руками.

### Сервисы

```typescript
// consent.service.ts
@Injectable()
class ConsentService {
  constructor(prisma: PrismaService, @Inject(CONSENT_CONFIG) cfg: ConsentConfig) {}

  getCurrentVersion(): string {
    return this.cfg.privacyPolicyVersion;
  }

  async acceptForUser(
    userId: string,
    documents: ConsentDocumentType[],
    ip?: string,
    ua?: string,
  ): Promise<void> {
    const version = this.cfg.privacyPolicyVersion;
    await this.prisma.$transaction(async (tx) => {
      for (const doc of documents) {
        await tx.consentRecord.create({
          data: {
            subjectType: 'USER',
            userId,
            documentType: doc,
            version,
            ip,
            userAgent: ua?.slice(0, 500),
          },
        });
      }
      await tx.user.update({
        where: { id: userId },
        data: { acceptedPrivacyPolicyVersion: version },
      });
    });
  }

  userRequiresConsent(acceptedVersion: string | null): boolean {
    return acceptedVersion !== this.cfg.privacyPolicyVersion;
  }

  async recordChildConsent(
    childId: string,
    parentUserId: string,
    ip?: string,
    ua?: string,
  ): Promise<void> {
    await this.prisma.consentRecord.create({
      data: {
        subjectType: 'CHILD',
        childId,
        userId: parentUserId,
        documentType: 'CHILD_14PLUS',
        version: '1.0',
        ip,
        userAgent: ua?.slice(0, 500),
      },
    });
  }
}
```

```typescript
// consent-required.guard.ts
@Injectable()
class ConsentRequiredGuard implements CanActivate {
  constructor(private consent: ConsentService) {}

  canActivate(ctx: ExecutionContext): boolean {
    const req = ctx.switchToHttp().getRequest();
    const user = req.user; // устанавливается JwtAuthGuard
    if (!user) return true; // нет юзера — пусть JwtAuthGuard отвергает
    if (this.consent.userRequiresConsent(user.acceptedPrivacyPolicyVersion)) {
      throw new ForbiddenException({
        code: 'consent_required',
        message: 'Policy update — accept new version',
      });
    }
    return true;
  }
}
```

Guard применяется через `@UseGuards(JwtAuthGuard, ConsentRequiredGuard)` на всех мутационных контроллерах: `ChildrenController`, `InvitesController`, `ChildDeviceController` (parent-endpoints), `UsersController` (PATCH /me). **Не применяется** на: `AuthController`, `UsersController.getMe`, `ConsentController.accept`, `UsersController.deleteMe` (чтобы юзер мог удалить аккаунт без согласия).

### Child-claim возраст-проверка

```typescript
// child-device.service.ts claim(...)
const childAge = child.dateOfBirth ? computeAgeYears(child.dateOfBirth, new Date()) : null;
if (childAge != null && childAge >= 14 && input.consent14Plus !== true) {
  throw new BadRequestException({
    code: 'consent14plus_required',
    message: 'Child aged 14+ requires consent14Plus flag',
  });
}
// ... после успешной claim:
```

## Security

- `ip` в `ConsentRecord` — nullable, максимум IPv6 (45 chars). Берём из `req.ip` (настроено через `trust proxy` в Caddy).
- `userAgent` — truncate до 500 chars (`ua?.slice(0, 500)`) для защиты от спама.
- `ConsentRequiredGuard` не применяется к logout и delete-me, чтобы юзер мог выйти/удалить без согласия.
- Timing одинаковый у всех 403 `consent_required` — не различает разные причины.
- Re-entry защита: `POST /me/consent` без изменений версии → `400 consent_already_accepted` (избегаем паразитных records).

4. Оператор ПДн — физ.адрес нужен? Рекомендую НЕ указывать на первой версии (добавим при ИП-регистрации), оставить только e-mail.
