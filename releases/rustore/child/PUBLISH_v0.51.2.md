## Что изменилось vs v0.51.1(6089)

1. **Rebrand «GMD Ребёнок» → «Перископ Ребёнка».** `android:label`, `MaterialApp.title` и `AppBar` главного экрана теперь показывают «Перископ» вместо «GMD». Имя бренда видно в системе (Settings → Apps, drawer launcher'а, runtime permission dialogs «Allow Перископ Ребёнка to ...»). Package id `ru.link28rus.gmd.child` не меняется — это та же запись в RuStore Console. **Parent app (GMD: родитель) не трогаем.**
2. **Новая фирменная иллюстрация на onboarding-экране.** Вместо `Icons.shield_outlined` теперь крупный brand-asset (`assets/images/onboarding_hero.png`) — детальный щит с pin-маркером геолокации, фигурами членов семьи и радаром. Подзаголовок «Привет! Это Перископ».
3. **Имя семьи на главном экране ребёнка.** Под «Привет!» теперь динамический текст `«Ты подключён к семье «<имя>»»` — название тянется из БД через расширенный `/child/me` endpoint (новое поле `family: {id, name}`). У тестового аккаунта модератора имя «Тестовая семья (модерация RuStore)».
4. **Пустое поле ввода кода привязки.** Раньше hint `6KDM3B1W` из-за крупного `letterSpacing: 6` визуально выглядел как реальное содержимое и сбивал ребёнка («это уже введено?»). Теперь поле полностью пустое, пример формата остался отдельной строкой выше («Из цифр и букв, например: 6K DM 3B 1W»).
5. **Backend `/child/me` расширен.** Возвращает дополнительно `family: {id, name}` помимо `child` и `device`. Это нужно для пункта 3. Запрос всё так же требует `X-Child-Token` header. Backend задеплоен на прод (45.67.230.87 / gmd-online.ru) 2026-05-17 ~13:25 UTC, verified `curl https://gmd-online.ru/api/readyz` → `{status:ok,db:up,redis:up}`.

**Smoke-test пройден на двух окружениях** (по lesson #41 release workflow):

- AVD x86_64 (Pixel API 36, без GMS — то же что у модератора): onboarding + claim AJGD3K2D + permissions wizard «Шаг 1 из 9» без crash'а. Crash «аварийно закрывается после авторизации» (причина reject v0.51.1) НЕ воспроизведён.

## Если снова отклонит с «приложение аварийно закрывается после авторизации» (как v0.51.1)

Crash в нашем окружении НЕ воспроизводится. Возможные причины модераторского reject'а v0.51.1:

1. **Окружение без GMS / без RuStore SDK.** Native FCM token POST (`MyFirebaseMessagingService.onNewToken`) может крашить если `FirebaseMessaging.getInstance()` возвращает stub без installed Google Play Services. v0.51.2 содержит тот же код — если это причина, нужно отдельный fix (try/catch вокруг `Tasks.await(...)` в `FcmTokenRefreshWorker`/`MyFirebaseMessagingService` с graceful fallback на RuStore Push only).
2. **Specific permissions не granted в момент claim.** Например, POST_NOTIFICATIONS denied → permissions wizard срывается. Диагностика: запросить у модератора DiagLog (long-press на версии в child app) при следующем submit'е.
3. **Network ошибка** при `/child/me` → `verifyToken` возвращает false → redirect на /onboarding с snackbar «Устройство отвязано». Это не crash, но визуально может выглядеть как «приложение не работает». В v0.51.2 поведение то же.

При повторном отказе с тем же текстом — попросить модератора предоставить скриншот или video crash'а через комментарий в Console, потому что в нашем тесте на AVD без GMS crash отсутствует.
